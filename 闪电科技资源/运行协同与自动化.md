# 闪电科技资源运行协同与自动化

[设计方案](设计方案.md) · [资源转化与来源计价](资源转化与来源计价.md) · [验证与待定事项](验证与待定事项.md)

资源反应堆以玩家为范围计算同时运行数量，以单台反应堆为范围保存周目与结算。玩家可以配置供电、暂停、内部升级和接口协同，形成快慢堆分工。自动化负责执行这些合法操作，不改变资源消耗和结算规则。

## 1 供能与内部时间

### 1.1 同时运行数量

设同一玩家在一次服务端结算中参与运行的资源反应堆数量为 `N`：

```text
数量耗电倍率 M(N) = 2^(N - 1)    （N >= 1）
```

| 同时运行台数 | 每台基础耗电倍率 |
| ---: | ---: |
| 1 | 1 |
| 2 | 2 |
| 3 | 4 |
| 4 | 8 |
| 5 | 16 |

主动暂停不占运行数量，也不推进内部时间、产生新资源或提供实时协同。暂停与恢复按同一结算边界处理，所有参与堆使用同一个 `N`，不能因为机器更新顺序不同分别享受单机倍率。

未完整加载的机器不推进、不提供协同，不占运行数量；首版不补算离线收益。网络变化和跨维度放置不改变玩家归属。资源转化器不参与这个计数。

供能不足是否继续占用运行数量，需要和后续退化状态机一起确定。不得先按单机价格推进、再按欠压状态从集合中移除，或在同一结算中反复改变数量以重复获取低成本推进。

### 1.2 平方根加速

正常运行且未触发待定退化机制时，采用下列基准关系：

```text
B_i = 第 i 台反应堆以 1 倍内部速度运行的基础功率
P_i = 本次真实消耗的功率
M   = 2^(N - 1)

s_i = sqrt(P_i / (B_i × M))
```

`B_i`、`P_i` 使用相同的功率单位，`s_i` 为内部时间推进倍率。加速基于真实消耗量，不读取电源标称输出、储能容量或仅模拟接收的能量。允许使用本机合法缓存供电，但不能把同一份能量用于多次推进。

数量惩罚作用于整条运行耗电曲线。保持相同速度时，每增加一台同时运行的反应堆，其余反应堆的所需功率也翻倍。不能只增加一个独立待机费，再让高功率推进绕过倍率。

内部时间支持小数和批量推进。不能按速度倍率逐次调用完整机器 tick；升级、资源耗尽、阶段重置和接口事件需要在有限工作量内处理，避免天文数值转成天文数量的循环。

### 1.3 数量取舍的数学基线

在机器基础功率、单位内部时间产量相同，总功率固定且平均分配，不考虑内部成长差异、协同、退化和阶段结算的简化模型中，合计推进速度相对单机为：

```text
相对合计速度 = sqrt(N / 2^(N - 1))
```

| 台数 | 相对合计速度 | 超过两台组合所需的净协同倍率，参照同一简化模型 |
| ---: | ---: | ---: |
| 1 | 100% | 与两台相同 |
| 2 | 100% | 1 |
| 3 | 约 86.6% | 大于约 1.155 |
| 4 | 约 70.7% | 大于约 1.414 |
| 5 | 约 55.9% | 大于约 1.789 |

这些是公式推导，不是实际游戏收益测试。一台和两台的纯推进效率并列；两台具有分工空间。实际应比较资源点净收益、完整与提前结算的周目时长、实物投入和供电成本，不能用瞬时推进总和证明三台或五台最优。

## 2 快慢堆与内部协同

### 2.1 独立周目的分工

允许一台反应堆在高产或高协同阶段持续运行，另一台发展出接口后接收内部资源加速成长，到达有利阶段后立即结算并重新开轮。三至五台可以形成多级供给、交替成长或不同路线组合；不预设固定数量必然最优。

示意流程：

1. 慢堆投入较完整的材料，发展到适合持续供给的阶段，暂不结算。
2. 快堆独立备料并开轮，用自身资源完成接口前置。
3. 快堆解锁接口后，接收慢堆允许输出的内部资源，加快后续升级。
4. 快堆达到当前策略目标后结算；慢堆保留自己的周目继续运行。
5. 快堆重新备料和发展，新周目的接口前置重新检查。

这里的“停留在巅峰”是维持运行状态，不是主动暂停。慢堆仍承担供电、同时运行数量惩罚和未来确定的欠压规则；它的角色不等于免费永久增益。

### 2.2 可传输资源和接口条件

接口只允许流程定义的内部资源类型。实际轮前投入的物品、流体和外部资源点不能经内部接口转移。接收内部资源不能直接补齐升级要求的外部实物，也不能赋予尚未解锁的阶段或接口。

来源和接收堆都必须属于允许协同的归属范围，且各自当前周目的接口、运行状态和能力满足条件。路由配置可跨轮保留，实际传输能力不得跨轮继承；新周目重新解锁前不接收缓存中的旧请求。

每次转移有真实的来源扣减与接收记录。接口数量、速率、转换损耗和资源类型由游戏内容定义，不能仅因同时在线就无条件给予满额协同。不同接口或多个目标共享来源可提供的额度。

已转移的内部资源归接收堆持有，不因来源堆后来暂停或结算而追溯扣回。接收堆可继续消耗已收到的库存；来源堆不能再次消费、输出或结算同一份资源。

来源尚未完成的发送请求不算已经转移。发生最终结算、接口失效、暂停或区块卸载时，应停止未完成传输并按实际交付量对账，不能留下可由下一轮重复领取的旧资源。

### 2.3 实时协同与储存协同

两种协同可以并存，但必须区分：

| 类型 | 作用 | 来源停止运行后 |
| --- | --- | --- |
| 内部资源转移 | 来源实际生产并交付可储存的虚拟资源 | 停止新供给；接收堆已收到的库存仍有效 |
| 实时协同 | 来源持续运行、提供处理能力或当期效率增益 | 停止提供；不能留下永久运行加成 |

允许玩家通过库存和暂停轮换安排生产，这是已有资源的利用。若希望同时运行三至五台具有效率优势，则部分协同应需要持续、实际的当期贡献，并验证它能覆盖数量惩罚。全部增益若都能无限储存，顺序运行少量反应堆可能更划算；不能在没有验证的情况下宣称多机同时运行必然最优。

同一 tick 的协同计算采用明确的资源快照与结算顺序，不能在相互连接的反应堆间无限递归放大。本轮新获得的资源或能力何时参与后续计算，由执行规则统一决定，不由方块更新顺序决定。

### 2.4 结算边界

每台反应堆的最终结算独立发生。结算前停止本台收发，已经完成的转移保持完成，未完成的转移保持未完成；内部状态完整清空后生成新的轮次身份。

来源堆的高阶段、奖励记录和接口资格不会复制给接收堆。接收堆必须用自己的实际成长达成结算条件。来源堆结算后，新的周目不能借旧接口或旧实时增益继续供给。

## 3 供能不足与退化

保留“供能不足时考虑退化”的设计方向，具体规则在设计增量游戏内容时确定。本稿不选择仅损失效率、损失生产单元或回退升级与阶段中的任何一种，也不填写阈值、速度、恢复费用或恢复公式。

需要结合实际游戏决定：

- 何为供能不足：单纯低速供能、低于最低维持要求，还是高阶段状态无法维持。
- 退化哪些状态，以及是否存在可逆与不可逆的部分。
- 缺电期间继续低速推进、停止推进或只执行退化的条件。
- 恢复供电后的恢复路径，及当前实际产出、接口供给与退化状态的关系。
- 欠压堆如何参与同时运行计数，避免集合与所需功率互相改变造成来回震荡。
- 退化使用真实运行时间还是内部时间；零供电下仍需退化时，不能依赖已经停止的内部时间推进。

主动暂停作为独立操作保留：冻结本轮推进，不占运行数量，不提供新产出与实时协同。不能用暂停、恢复、拆装或重载把已经发生的退化直接恢复为未退化状态。具体暂停与退化规则仍需在内容设计时一起校验。

## 4 自动化模块

### 4.1 外部持久能力

首次完整通关后，玩家获得同一玩法的永久自动化资格，使后续周目从开局或很早就能自动运行。首次通关条件由流程配置，不要求穷尽所有可选挑战；提前结算本身不等于完整通关。

资格按玩家保留，不因新建反应堆或单堆最终结算而丢失。模块、备料清单、策略和脚本保存在外部，最终结算后保留；内部生产单元、升级和协同接口照常重置。流程版本管理需要区分规则修订与全新玩法，不能因为普通数值修订就无意中要求所有玩家重新手动解锁。

模块可以在下一轮开局或极早期执行已保存策略，制作与使用门槛不能再次要求该轮手动推进至中后期。后续玩法围绕长期策略优化，而不是重复手动执行已经熟悉的流程。模块配方和极早期门槛的具体形式待定。

永久资格只提供操控便利，不减少升级材料或费用，不提高生产、协同或结算倍率。玩家仍可选择手动运行；跨存档和跨服的资格继承范围另行决定。

### 4.2 可配置策略

无需编程即可配置常见操作：

- 本轮物资清单、备料上限、备齐后启动。
- 升级优先级、购买条件、购买数量和需要保留的本轮材料。
- 阶段重置条件及不同阶段采用的策略。
- 接口资源、来源与目标、接收目标量和输出保留量。
- 运行与暂停条件、供电预算及快慢堆角色切换。
- 达到目标、缺料、预期收益下降等情况下的最终结算条件。
- 结算后是否自动进入下一轮，及下轮采用的物资清单。

缺料不强制结算，策略可以尝试其他仍可执行的路径。系统应展示当前受阻原因、预计结算点数和最近采取的操作，便于玩家调试。

### 4.3 玩家控制脚本

玩家脚本读取允许访问的本轮状态、库存、升级目录、供电信息、协同伙伴状态和结算预览，提交与界面相同的合法动作。升级、接口转移、阶段重置和最终结算都由服务端统一校验和扣费。

玩家脚本不得直接改余额、修改奖励函数、解锁接口、生成实物或写入任意周目状态，也不能取得其他玩家私有存档。脚本能力应限制在游戏控制 API 内，运行时间与动作数量受预算约束，防止无限循环阻塞服务器。

自动化按状态变化或适当间隔运行，重复指令不会重复消费或结算。脚本引擎、语言、调试界面和具体 API 待实现阶段确定。

### 4.4 流程作者脚本

整合包或服主配置的流程脚本定义游戏规则：阶段、生产单元、升级成本、实物要求、接口资源与协同关系、阶段重置、提前与完整结算的奖励及上限。它与玩家操控脚本分开授权。

每轮绑定规则版本，已经锁定的物资和成长过程不能被重载静默改价。新规则何时生效、旧版本如何保留和迁移由版本策略规定；无法兼容的改动必须有明确处理，不可重算旧奖励后再次发放。

## 5 界面信息

控制器至少需要显示：所属玩家、本台轮次与阶段、运行或暂停状态、玩家当前运行台数及耗电倍率、实际消耗功率与内部推进倍率、本轮投入剩余量、可用升级、接口收发与实时协同来源、当前结算预览，以及自动化策略和受阻原因。

恢复一台堆前，应能看到同时运行数量和其他堆供电需求将如何变化。欠压与退化的信息随最终规则补充，不把“暂停”和“供能不足”显示成同一个状态。

最终结算预览需说明仅本台重置、资源点奖励以及本台全部轮内余额将被清空。自动化可依据同一份预览作出决定，不需要每轮人工确认。
