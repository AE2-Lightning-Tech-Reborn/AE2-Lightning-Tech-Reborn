更新：2026-11-01。本文记录当前玩法方向，替代首版原型中广泛保留关键科技的规则。既有网页原型仅验证了小规模有限物质循环；深层玩法、现实耗时与最终经济尚未实现或完成平衡。

## 1 深度与终局目标

设计一套原创的复杂增量玩法，参考增量树的多层成长、挑战、分支和重置机制。The Modding Tree 用于原型框架，不直接照搬成品游戏的科技树、内容或经济。

外部物质、支撑和特殊模块决定本轮能够支撑的内部发展深度。内部操作决定怎样使用这笔预算：研究顺序、资产分配、重复建设、重置时机、通讯支援与最终生产都会影响结果。纵向每跨越一个主要工艺层级，单位原料的结算产额以约一个数量级增长为设计方向；横向节点可以改变吞吐、研究成本、挑战条件或加工路径，不要求每一个升级都乘十。

满配外部投入、正常基准供电与服务器 tick 率、接近最优的内部操作序列，目标是在 **现实经过约 3–24 小时** 内完成最高层发展和最终生产，接近单轮 `long` 上限 `9,223,372,036,854,775,807`（约 `9.22 × 10^18`）资源点。这是待校准的目标，不是已有测量结果；不是 Minecraft 昼夜，也不是加速后的内部小时。

一般策略可以耗时更久或停在较低层。反复重建、错误研究、过早转换和不当通讯都可能耗掉突破所需的原料，使本轮再也无法登顶；不保证每个脚本放得够久就能通关。仅等待较久、但资源分配正确的策略仍可能最终完成，因为当前没有 24 小时强制截止。更多 FE 主要加快过程，不能修复已浪费的物质预算。

曾讨论的八层结构、阶段名称、逐层成本乘 15–30 和八小时样例路线均为候选，不作为确定参数。需要从最高产额、有限投入、突破成本和实际运行时间一起反推层数与曲线。

## 2 外层运行与内部嵌套重置

“两层”区分外部投入运行与内部成长，不限制内部只能有一种重置。一次外层运行可以包含多级嵌套重置、挑战与多轮路线安排。

```text
外层启动：锁定物质、支撑、特殊模块、升级物耗倍率和规则版本
  发展下层生产与研究，达到实际突破条件
  内部重置：兑换本层资产，清空下层成长，由脚本重新建设
  重复发展：调整资产分配、路线和重置时机
  更高层突破：清掉更多下层资产，只保留规定的少量成长
  通讯接口：付费取得合格支援，减少部分区段的重复建设
  最终生产：按所用工艺将剩余原料转成结算物质
外层最终结算：只交付一次资源点，结束本轮并清空内部状态
```

低层转换始终是一条可走的路径。玩家可以停止突破，慢慢把剩余原料加工成结算物质，只是速度慢、单位原料产额低。已经转换的原料不能再用来研究或高层加工；已形成的结算物质不会因随后升级而追溯升值。

外层可以提前结算，缺料不强制零收益或自动结束。最终结算仍只清空本台，其他堆的周目与已完成转移不回滚。

## 3 深度清空与两本永久账

脚本负责重复重建，玩家负责设计重建过程。因此不为了减少手动点击而普遍保留普通研究、设施、旧关键科技或低层里程碑。默认清空下层，只留下本次重置赚取的上层资产、更高层状态和明确写出的少量例外。

这里的“永久账”仅指同一次外层运行中的所有内部重置。外层最终结算后仍按原有规则结束本轮，不返还未用原料，不把内部库存带入下次投入。

| 状态 | 任意内部重置 | 外层最终结算 |
| --- | --- | --- |
| 未消耗的原始物质 | 始终保留当前余额；不能恢复已经花掉的部分 | 清空，不返还 |
| 已转换出来的结算物质与对应价值记录 | 始终保留；不因后续工艺提高而重新计价 | 计入唯一结算后清除轮内记录 |
| 普通中间材料、内部货币、设施、研究与挑战进度 | 默认按重置范围清除；不保证中间材料保留 | 清除 |
| 本次取得的上层核心资产及更高层状态 | 按重置层级保留；再上一层突破可以清掉旧核心 | 清除 |
| 少量保留能力 | 明确作用范围，通常只保留紧邻层的少量状态；可被更高层重置清掉 | 清除 |
| 当前通讯接口资格 | 保留至其规定区段边界，见下节；不恢复库存和设施 | 清除 |
| 支撑、锁定的升级倍率和特殊模块效果 | 不刷新、不重新发放、不改变开局配置 | 本轮效果结束 |
| 外部自动化资格、脚本、配置、说明与历史记录 | 保留；脚本动作仍需重新满足解锁和费用条件 | 保留 |
| 已交付外部的资源点 | 不受内部重置影响 | 保留 |

建设、研究、加工和通讯照常扣减原始物质。重置设施不退还建设费；清除中间材料需计入损耗。所有资源遵守同一物质当量账，不凭空补料或把同一份物质同时计入库存和成果。

重置次数本身不发奖。上层资产来自这一轮实际完成的研究、挑战或加工成果，并按规则兑换；空点重置、重复兑换同一成果不能增加资产。上层奖励优先改变重建方法，如基础吞吐、起步研究成本、可选路线和批量建设能力，而非逐步累积“下面数层全部永久保留”。

## 4 研究专精与路线安排

保留对数科技点作为研究机制，但不要求全部高层使用同一货币或公式。首个研究层可采用：

```text
X = 本子轮累计完成的研究量
T_total = floor(A × log2(1 + X / X0))
T_available = T_total - T_spent
```

累计研究量与已花科技点分开记账，不在每次更新时重新发放整份科技点。重置清除对应下层的研究量与点数；要保留的成果须明确转换为上层资产，普通未花点数不能默认跨层囤积。

基础路线不设硬互斥，不以额外的统一承载上限强制只能研究一条。有限材料、研究量的对数增长与深层成本形成自然专精；浅层辅修和跨轮组合仍有价值。对数没有数学上界，必须连同研究材料成本验证实际可达范围，不能只凭公式声称必然无法兼修。

策略要共同决定：本轮研究多深、何时重置、累计几轮再突破、上层资产怎样分配、何时停止投资并投入最终生产。科技点、升级材料利用率、加工产额是不同维度，不得混成一个倍率。

## 5 通讯接口划分重建区段

在少数层级开放通讯接口，把需要反复推进的下层分成区段。接口首先由本台达到前置条件后解锁；当前接口资格在该区段内的内部重置后仍可使用，高层接口可以替换重建起点。跨越更高区段时保留哪些旧接口须明列，外层结算则全部清空。接口层数与具体保留范围仍待内容表确定。

通讯可以辅助本机重建，也可以交付合格资源、替代部分下层生产和重复子轮。跳过范围由接口能力决定，不能直接复制来源堆的阶段完成、上层资产或结算奖励；接收堆仍需完成当前区段的本地突破条件。

所有帮助消耗真实的有限原始物质。候选分摊方式是来源堆支付生产耗材，接收堆支付按实际交付量及支援深度计算的原始物质通讯费；费率与分摊尚未定案。接口数量或消息条数不能替代实际受益量计费。普通输入资源服从后续内部重置，过早购买后被清掉属于策略浪费。

需要比较自建、只买瓶颈、购买整段支援和延后接收。优化包含买多少、何时买、向谁买、跳过多深，也要计入来源堆的建设、FE 和同时运行数量惩罚。每份资源真实扣增，受来源预算与接收承载约束，详见[通讯协同](运行协同与自动化.md#25-通讯与重建区段)。

## 6 外部参数与利用率

外部升级材料利用率定义为 `η = 1 / K`，允许 10%–100%。100% 对应升级物耗 ×1，50% 对应 ×2，10% 对应 ×10；低于 10%、超过 100% 或非有限输入不能启动。`K` 只作用于升级物质成本，不扣初始投料，不再次作用于普通加工或最终结算。

低层工艺“利用率低”在玩法描述中指单位原料的结算产额低，不能与上述升级材料利用率混用。界面分别标出升级材料利用率、处理吞吐和单位原料产额。

网页模型可继续使用数值框与滑块输入物质量和利用率。正式启动锁定这些输入，运行、暂停与任意内部重置均不能补料、改值或重发模块；只有下一次外层启动才能更换配置。Minecraft 阶段再将真实物品、支撑比和 Sigmoid 接入相同边界。

## 7 自动化与真实时间

深层玩法以脚本重建为基础，不能要求玩家手动重复操作完整的 3–24 小时终局流程。首次用于授予持久自动化资格的核心流程应当较早、规模可控，与最高层及 `long` 产出目标分开定义；后续外层运行从开局或极早期使用保留策略。具体解锁节点仍待内容设计，不能把自动化锁到最高层之后。

常见策略可以通过预设与配置完成，玩家 JS 用于更细的顺序、预算和通讯优化。脚本没有生产特权。每个真实服务端 tick 最多运行一次脚本决策和一次核心推进，加速进入公式，不增加循环次数；暂停、卸载与离线没有收益。低 TPS 或后台限流会延长现实完成时间。完整技术边界见[JS 后端与 GraalJS 运行架构](JS后端与GraalJS运行架构.md)。

界面应展示嵌套层级、各层重置清除项、原料余额、结算物质、研究花费、突破条件、接口保留范围和实际费用，便于脚本调试和比较策略。
