# 交接说明：增量游戏（奇点里的宇宙）

2026-11-19。给新会话用。这个项目是给 AE2 闪电科技模组做的增量游戏玩法原型，先在 Node 里验证玩法，暂不接入 Minecraft。

## 分工

- **主代理负责游戏设计**：给出明确的规格（机制、要回答的问题、验收标准），根据测试结果判断设计是否成立。不写实现代码。
- **实现代理负责代码实现和数值测试**：用 `subagent` 工具启动，线路 `pixelstarrysky-gpt` / `gpt-6.2-astra`，推理强度 `xhigh`。按规格改 `reactor-prototype`，保持测试通过，跑打法对比和数值扫描，把结果和发现的问题报回来。

## 现状

- 原型规则版本 `0.4.0-U4`，实现了原初、凝聚两个时代，36 项测试通过。
- 试玩界面 `reactor-prototype/web/reactor.html`。**这一版用户还没有试玩反馈**，界面也没有在真实浏览器里验证过。
- 测试要用 `node test/core.test.js` 这种方式逐个运行；`node --test` 在沙箱里会报 `spawn EPERM`。

## 已知缺陷（下一轮设计要处理）

1. 结构里晶核偏强，尘云几乎没有存在感。
2. 规律“自激”“余辉”从来不是最优选择，是陷阱选项。
3. 最优打法基本不随宇宙规模变化。
4. 抽取的最后一两分钟没有事可做。
5. 抽取按核心概念应属于最后一个时代，原型里暂时放在凝聚时代。

## 还没做的

恒星、星系、视界三个时代；更多级样本；增强件；分级支撑；挑战宇宙与特殊样本；可选的随机模块；玩家脚本接口；多堆协同（已决定延后）。

## 用户的偏好

- 先设计、再实现；要有这个游戏自己的内容，不要只把框架搭出来。
- 每个机制都要能回答“什么时候不该用它”；多种东西要搭配着用才最强，不能是谁划算买谁。
- 不要永久成长；跨轮的成长靠外部产线做一次性的增强件。
- 数值细节交给设计方决定，但规则上要有明确的上限，上限用渐近曲线实现，不用截断。
- 交互要清楚：逐步解锁，每一步知道该做什么；没成功的操作要说原因。
