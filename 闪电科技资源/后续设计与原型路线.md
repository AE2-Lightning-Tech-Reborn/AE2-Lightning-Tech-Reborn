# 闪电科技资源后续设计与原型路线

更新：2026-10-30。本文是后续工作的建议顺序与验收目标，不表示已经开始实现或完成平衡验证。当前先验证有限物质条件下的配料、升级和多轮策略，再扩大内容和 Minecraft 接入。

## 1 先回答什么

核心方向已经足够明确：物质决定可用库存，有限分级支撑决定承载和升级物耗，特殊模块提供本轮加成，内部科技把库存转为可结算成果。现在最需要确认的是这些选择是否有各自适用的条件。

| 问题 | 原型应给出的证据 |
| --- | --- |
| 多装物质还是多留支撑余量 | 在同一外部预算内比较最终点数、升级消耗、轮长与剩余物质，不能只比较 `K` |
| 低级载体还是高级压缩物 | 分别在外部基础资源紧张、支撑紧张的条件下比较，验证两个效率方向都能影响选择 |
| 升级到什么程度 | 找到升级消耗与后续吞吐、产额收益的回本条件，保留有意义的短轮和深轮 |
| 特殊模块是否值得投入 | 把模块本身的制作成本计入，观察哪些路线受益，而非所有配方无条件加同一枚 |
| 慢堆为何值得维持 | 支援带来的机群收益能否覆盖它的建设、材料、供电和运行数量成本，以及何时需要交接 |
| 为什么结束当前周目 | 有限库存、升级回本和周转效率是否已足够形成停止条件，再决定是否需要寿命或退化 |

不预设每种策略都在所有条件下同样有效。若某个选择在全部合理场景都被另一选择压过，应先修正其成本或作用，再增加更多等级。

## 2 第一阶段：最小内容与参数表

建议先准备一套可以手算、能够跑完一轮的小内容表。以下数量和路线仅用于控制原型范围，不是正式内容定案。

| 表 | 建议的最小内容 | 必须写明的字段 |
| --- | --- | --- |
| 物质载体 | 3 档，允许混装 | 实物来源、外部配方成本、内部物质量、支撑需求 |
| 支撑 | 3 档、一个有限数量上限 | 单元成本、支撑值、允许数量、启动余量 |
| 升级曲线 | 一组候选参数及附近几组对照 | `K_min、K_max、R_c、a`，精度、舍入与批量购买口径 |
| 科技与工艺 | 约 3 个阶段，至少一处路线取舍 | 前置、升级基础物耗、实际物耗、加工吞吐、物质消耗、成果产额、阶段重置保留项 |
| 特殊模块 | 先不装模块建立基线，再加入约 2 个候选 | 一次性成本、解锁效果、何时生效、互斥与叠加、结算清除项 |
| 结算 | 一种主要可结算成果与完整通关目标 | 实际成果来源、点数报价、取整、上限、提前结算规则 |

必须先定义基础物质、加工产物、残余物与损耗的当量关系。升级费用、加工消耗和共享消耗分别记录，不能用同一个模糊的“资源利用率”混在一起。`K` 只乘科技升级的基础物耗。

科技内容建议先区分处理速度和单位物质产额。新科技应同时带来更高产率与更大的基础资源消耗，并让玩家能根据剩余库存判断是否值得升级。首批特殊模块可以尝试研究专精、某类工艺强化或协同能力，但具体选择应由上述路线需要决定。

这一阶段的交付是一份可执行参数表及若干手算样例：同一批库存分别不升级、部分升级、升级到底，以及不同支撑余量下各自剩余多少物质、形成多少成果。它只检查规则是否自洽，不承担最终平衡结论。

## 3 第二阶段：独立单堆数值原型

先做与方块、网络和渲染解耦的模拟核心。输入为本轮物质、支撑、模块、供电方案和行动序列，输出为状态轨迹、物质收支、实际耗电、成果与结算记录。同一规则版本、输入和操作顺序应产生相同结果。

先使用最小状态：准备、运行、暂停、最终结算及待交付。实现启动锁定、科技升级、加工、阶段重置、提前结算；关闭跨堆输入，不默认加入寿命、熵和退化。欠压行为尚未定案，第一轮策略比较使用明确的正常供电范围；实现接入前必须补齐低功率与零功率规则。

比较至少包括：

- 相同外部原料预算下的低级、高级与混合载体；另做相同支撑数量和等级下的承载比较，不能将两种比较口径混为一谈。
- 满载、预留部分余量、较大余量的升级消耗和总成果。
- 不升级、部分升级、尽早升级与保留物质后升级的差异。
- 短轮与深轮在单轮成果、连续多轮产率和实际投入上的差异。
- 不用特殊模块的基线，以及支付模块成本后的路线收益。
- 从正常世界资源完成首轮的路径，以及点数采购、外部生产和加工共同参与的后续循环。

记录的指标至少有：每轮实际点数、原料种类和数量、支撑与模块消耗、FE、轮长、升级消耗、未使用物质、连续运行的结算间隔。不把不同物品未经定价直接相减成一个“净收益”；若使用点数折算，需明确采用哪一版真实来源报价。

单轮收益和长期效率分别比较。连续多轮测量应包括备料、启动、结算交付和重开，不能只截取稳定加工阶段。内部时间与现实运行时间分开记录，供电影响两者的换算。

通过条件是：物质收支闭合、重复操作不生成免费资源、阶段重置不恢复预算、倍率锁定且仅用于升级；至少存在能解释原因的配料和升级取舍，并能展示什么时候继续升级不再划算。若有限库存已经能形成清楚的停止条件，先不增加晚结算损失机制。

## 4 第三阶段：双堆成本与交接

在单堆成立后，先增加一种需要持续支付有限材料的实时支援，再研究内部物质传输。这样可以分别判断“协同有没有用”和“接收预算怎样记账”，不把两类未知同时混入首次实验。

双堆比较使用相同的总外部投入和总功率，并计入 `2^(N - 1)` 数量耗电倍率。对照至少包括单堆连续运行、两堆同时独立运行、两堆顺序运行、慢堆支援快堆以及支援堆交接。不能只统计接收堆加速了多少。

支援费用必须随实际支援工作量或受益强度计费。降低来源堆的内部速度，不能在保留完整支援效果的同时把有限材料费用降为零；接收方未运行或不能利用时，不能凭空产生可积累的成果。具体结算单位由原型选定。

开放物质传输前，确定接收负载、开局预留和累计接收规则。至少覆盖“低投料获得较低 `K` 后大量接收”“转出再转入”“循环互传”“暂停后消费已有库存”“来源结算时仍有在途请求”等情况。优先采用易说明、能对账的规则，不因库存空间释放就默认重发免费接收额度。

通过条件是：每份资源只有一个持有者，传输和支援均有实际成本，慢堆累计输出受有限投入约束；暂停、结算与交接没有重复收益。是否需要三至五台同时运行，应依据双堆结果再增加内容，不能只按理想协同倍率推定。

## 5 第四阶段：可玩的界面与多轮自动化

给已经成立的模型增加简洁的交互原型，验证玩家能否理解选择。准备页应同时展示物质量、支撑数量与负载、升级倍率和模块；升级页展示乘倍率后的实际价格及剩余物质；结算页展示当前成果、点数和将清空的内容。

先让玩家手动完成一次明确的核心流程，再验证后续周目从开局或极早期使用保留策略。第一版策略只需覆盖备料、升级优先级、保留库存、协同条件、结算和重开，不必先完成任意语言的脚本系统。手动和自动化共用同一动作校验与成本。

检查自动化是否能连续运行多轮、是否能说明受阻原因，以及修改投入或升级顺序后能否比较整段运行结果。首次完整通关资格、持久自动化设备与一次性特殊模块必须在界面上区分。

题材包装、阶段命名和表现可在此时收敛。微型宇宙或物质演化服务于有限物质转换的规则；不为了表现先引入居民返还、文明延续等额外生命周期。是否复用现有增量游戏，也应按模型是否适配、规则能否脱离其原有永久成长、许可证与技术接入成本另行评估，当前没有选定复用项目。

## 6 第五阶段：Minecraft 最小实现

进入实现前，确定独立仓库、首发 Minecraft 版本与加载器，以及 AE2、LT、TB 的依赖范围。现有文档位于 LT Reborn，不等于将新附属代码直接放入 LT；不以建设下一代通用多方块框架为前置。

首个可验证实现覆盖一台反应堆、一组实际物质与支撑配方、必要的模块样例和一种来源的转化器，走通外部备料、启动锁定、FE 推进、升级加工、唯一结算与实物交付。随后接入已验证的双堆规则和连续自动化。

优先验证持久化与事务边界：启动扣料、暂停和卸载、重启恢复、并发传输、输出受阻、结算重试、下一轮启动和规则版本变化。资源点 AEKey 与 ME 任务链路需实际执行验证；来源兼容再逐项扩展，不把单一来源走通当成全部第三方配方和资源类型兼容。

数值原型只提供规则与策略证据。真实服务器的处理预算、区块加载、ME 网络变化和多玩家归属需要独立验收；大数推进不能退化为逐个内部 tick 或逐份物品循环。

## 7 最近一项可开展的工作

下一项建议是完成第一阶段的最小参数表，并做单堆数值原型。先回答“同样的外部投入，满载还是留余量、升级几次、何时结束更合适”，再扩大科技树和设计双堆专精。

这一过程中暂不定最终 Sigmoid 数值，不默认加入寿命与晚结算惩罚，也不先铺满模块和高阶内容。每次扩展应针对已观察到的问题，并保留能够重复比较的基线。
