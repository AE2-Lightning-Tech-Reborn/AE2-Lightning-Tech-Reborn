| 项目 | 本次环境 |

依赖清单分别记录 Maven 坐标、文件大小和 SHA-256。隔离运行时包含 `org.graalvm.js:js-isolate-darwin-aarch64-community:25.4.4.1.1`；该文件 SHA-256 为 `c653da0ec505e03f0107257835fdef75e60823fe83ded9b0bed9d4dd479bbabc`。普通模式所用 JAR 合计 `69,977,684` 字节，隔离模式所用组合合计 `79,963,165` 字节；这是压缩文件体积，不是运行内存或每玩家开销，两组也不是要求一起打包的依赖集合。

实际选版仍需重新核对 Maven 依赖、原生平台和许可证。测试中遇到的 community 别名 POM 有弃用提示，不能把这一组试验坐标直接确定为发布方案。官方入口为 [Polyglot 嵌入说明](https://www.graalvm.org/latest/reference-manual/embed-languages/)，页面会随版本变化。

## 2 JS 与 Lua 的辅助探针

Rhino 和 LuaJ 的小回调分别测得约 `0.706 μs` 和 `0.250 μs`；这个差异不足以选择完整后端语言。两者的循环计数均能终止探针中的死循环，包含试图捕获错误继续运行的情况。

创建一百万字符字符串的原生调用，在 Rhino 指令观察器中计数为 0，在 LuaJ 中仅为 7；说明这类指令计数本身不是堆内存配额。普通 JS `Number` 和本次 LuaJ 数值在 `2^53` 边界都出现相邻整数无法区分，Rhino 的 BigInt 边界运算通过。这些结果不推广到全部 Lua 运行时或所有运行模式。

选择 JS 的主要理由是与现有玩法核心共用语言和数据协议，而非宣称 JS 在所有微测试中更快。GraalJS 隔离能力与实际嵌入结果是后续验证重点。

## 3 固定真实帧的小模型

`fixed-tick-results.json` 记录 10,000 个随机案例全部通过：批量算术与同一冻结帧规则的参考实现一致，预留原料正确、余额非负、加权物质守恒，新生产到下一帧才可用，通讯不能在同一阶段再次转发。

| 内部倍率 | 1,000 个真实帧对应的脚本回调数 |
| ---: | ---: |
| 1 | 1,000 |
| 1,000,000 | 1,000 |
| 1,000,000,000,000,000,000 | 1,000 |

该实验说明可以把倍率放进公式而保持调用次数不变。它不证明与连续模拟或旧子步循环等价，也没有覆盖 Minecraft、真实脚本调度、多线程交接或完整玩法平衡。

## 4 GraalJS 能力与限额

`GraalProbe.java` 在普通和隔离两种模式下检查大整数、语法、宿主访问、回调和超限行为。结果摘要分别保存在 `regular-results.txt` 与 `isolated-results.txt`。

| 检查 | 实际观测 |
| --- | --- |
| BigInt | `long` 边界附近整数计算保持精确 |
| 现代语法 | 可选链与空值合并运算通过 |
| 宿主访问 | `Java.type` 查找宿主类被阻止；不能仅凭全局名称存在与否判断权限 |
| 语句限额 | 配置 5,000，执行到 5,001 时终止，包含 `catch/finally` 尝试继续的样例 |
| 已超限 Context | 继续调用失败；新建 Context 后正常运行 |
| 隔离模式 CPU | 配置 200ms，报告 guest CPU 207ms，墙钟约 209.485ms 后停止 |
| 隔离模式堆 | 配置 16MiB（16,777,216 字节），报告至少 16,871,848 字节时取消 |

探针还配置了隔离堆总上限 256MB、单线程、AST／栈深度和输出限制，但没有逐项做穷尽故障测试，尤其不能把“配置成功”写成隔离堆压力验收通过。CPU 和内存测试只证明本次样例触发了相应限制。

[官方沙箱说明](https://www.graalvm.org/latest/security-guide/sandboxing/)明确限额取消会使 Context 不再可用；CPU 限额按周期检查，可能超过配置值后才生效。因此生产设计采用有界调度、暂存动作、显式 `memory` 和超限后重建环境，不将探针中的 200ms 或 16MiB 直接作为正式参数。

## 5 回调成本

小回调包含八次循环和简单分支。先预热 20,000 次，再测五组各 100,000 次，取每次调用平均耗时的组间中位数。另测一组每次调用前执行 `resetLimits()` 的 100,000 次循环，该行不是五组中位数。

更接近策略接口的样例读取八个研究节点，解析 JSON，以 BigInt 检查预算与保留量，输出动作和 `memory` 的 JSON；包含逐次 `resetLimits()`。先预热 10,000 次，再测五组各 20,000 次，取组间中位数。

| 样例 | 普通模式（解释执行） | `UNTRUSTED` 隔离模式 |
| --- | ---: | ---: |
| 小回调，中位数 | 0.447 μs | 1.897 μs |
| 小回调，每次重置额度，单组均值 | 0.510 μs | 3.218 μs |
| 八节点 BigInt／JSON 策略，中位数 | 7.959 μs | 17.931 μs |

初次建环境并执行分别约 321.890ms 与 175.038ms，只是本次单次观测，不据此判断冷启动优劣。循环使用已经建好的环境，不能把每次回调成本与新建 Context 成本混为一谈。

没有测量完整科技树、复杂玩家脚本、多玩家吞吐、P95／P99 尾延迟、24 小时内存、服务器 TPS 或所有宿主 JDK。结果支持继续验证粗粒度快照接口，不能直接换算为服务器支持的反应堆台数。

## 6 旧玩法模型原样嵌入

将独立网页原型的 `dist/js/reactor-model.js` 原样加载到 GraalJS `UNTRUSTED` 隔离环境，并在 Node VM 中执行同一 `model-harness.js`；不提供 `window`、`document` 或 `localStorage`。被测源码 SHA-256：

```text
cabdee561ded397b7a4c97a324f941a6de1e99e66bce143d87ae67a959717018
```

两边各通过 13 项检查，覆盖无界面启动、物质账本、存档校验、恢复后继续运行一致、内部重置及成果保留、三子轮自动完成、最终存档与重复结算拒绝。完整自动路线使用 0.05 秒模型步长，均在 12,365 步后得到 48,437 点、3 个子轮，结果摘要一致，记录于 `model-embedding-results.json`。

这里的步数来自独立 harness，不是实际 Minecraft tick 或现实经过时间。该路线和步长也不同于[首版固定策略表](原型数值记录.md)，不能将两张表的数值差异当作新版本产额变化。测试对比的是检查结果与最终摘要，不宣称逐步全部状态已经跨引擎逐字段比对。

已有模型本身能脱离浏览器，说明玩法后端可以继续保留在 JS。TMT 外壳仍使用 Vue、DOM、`Date`、页面定时器和浏览器存储，需与核心分离；旧模型还使用 `Number`，其 `advance()` 仍包含 0.25 秒子步循环。正式的固定真实帧、精确账本与深层玩法尚需在 JS 中改造。

## 7 结论范围

本次确认独立环境中的模型嵌入、若干 GraalJS 限额行为和固定帧算术可行。选用完整 JS 后端不需要先将经济逻辑移植到 Java。未确认的是最终打包、NeoForge 类加载、全部平台、多人长期负载、付费帧与结算恢复协议、深层平衡及现实时间目标。

下一轮应在同一个 JS 核心上建立确定性回放和状态账本检查，再接真实世界桥；具体检查项目见[验证与待定事项](验证与待定事项.md)。
