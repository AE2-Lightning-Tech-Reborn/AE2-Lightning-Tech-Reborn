# 大型过载处理工厂总体设计

[文档首页](../README.md) · [工厂设计目录](设计目录.md)

适用环境：Minecraft 1.21.1、NeoForge、Java 21。本文是待实现的设计方案，不代表功能已经发布。

首版采用固定多方块结构，背面有九个功能仓位。内部中央使用 T1–T4 处理核心时，成型为普通工厂，基础开放反应仓和过载工厂配方，其他工艺由工艺核心仓中的对应核心解锁；中央使用苍穹转换核心时，成型为只处理苍穹转换配方的专用工厂。两条路线共用样板仓、按单／被动模式、全厂加工额度与 0t 执行器。普通工厂还可通过水晶仓生成催化处理样板；加工所需能量默认从任务所属 ME 网络取得，也可安装能源输入仓供电。

## 本代独立实现与下一代规划

本代先在 AE2 Lightning Tech Reborn 内独立实现大型过载处理工厂：固定结构、专用仓室、实际配方绑定、材料账本、费用、调度和恢复都由 LT 工厂代码承担。[通用多方块框架](../通用多方块框架/设计总览.md)留到下一代，不以框架完成或独立验收作为本厂开发前置。

本代按工厂实际需求组织内部类，直接复用已存在且适用的配方目录、ME 接入和批量回传协议。不新增 TB 结构框架、通用八类仓室、数据驱动形状生成器或通用机器运行时，也不把未来框架 API 作为当前依赖。

本机参数与安装白名单以本目录为准。下一代框架中的 4 tick 默认下限、输入输出仓、可变模板和独立并行仓不适用于本厂的 0t 配置。

## 功能边界

| 保留的内容 | 行为 |
| --- | --- |
| 固定结构、控制器、外壳和框架 | 提供成形检查、预览、缺料提示和自动搭建 |
| T1–T4 处理核心 | 集中决定每 tick 加工份数、FE 吞吐及储能 |
| 苍穹转换核心成型 | 替代内部中央的 T1–T4 核心，原地成型为苍穹转换专用工厂，每 tick 1,024 次源配方操作、0t 完成 |
| 工艺核心仓 | 每厂最多一个；普通工厂放入不同工艺核心后解锁对应额外配方族，不提供加速；苍穹专用状态不启用这些授权 |
| 普通／扩展样板仓 | 每仓 36／144 槽，允许多仓混装，保存真实加工样板，按单或被动执行 |
| 水晶仓 | 普通工厂保存真实催化材料，自动暴露对应的虚拟处理样板，与样板仓共用执行能力 |
| 能源输入仓 | 可选的外部 FE 入口，与 ME 供电共享整机功率限制 |
| 工厂闪电成本 | 普通工厂每次源配方至少 1 高压；苍穹专用每次 1 极高压；两者允许代偿 |
| 0t 加工 | 材料、能量和接收条件满足后，在本次执行中完成，不保留加工进度条 |
| 被动模式 | 每 100 tick 检查一次；合成完成后额外唤醒；不自动请求 AE 合成缺料 |
| 真实配方绑定与恢复 | 首次实际执行才初始化执行缓存，重载后惰性重建，保留未交付资源 |

本机首版不接入普通输入/输出仓、ME 输入/输出仓、并行仓或协同调度仓。工艺核心仓、水晶仓和能源输入仓不分 T 级，样板仓仅区分两种容量。不提供原料标记、拉取/库存模式、低水位、无限本地仓储、独立输入输出网络配置和全网自动搜方。需要处理什么由仓内样板或催化材料决定。

新工厂使用独立注册 ID，与既有过载工厂、普通水晶催化器及猪咪水晶催化器并存。它不改这些机器的配方、运行速度和物品 ID。苍穹路线复用现有苍穹转换核心方块作为中央成员；未被有效工厂接管时仍保留原单机行为。第三方加工按已实现的配方适配器逐类接入，不把任意加工样板视为可以直接生成产物的授权。


## 界面

控制器页面显示中央核心、当前“普通过载加工／苍穹转换专用”用途、九仓位占用、工艺解锁状态、供电策略、整机运行情况和恢复诊断。样板仓显示实体样板、页码、被动开关、条目状态与失败原因；水晶仓显示真实材料、自动生成的处理条目及被动选择；工艺核心仓显示核心与解锁工艺。苍穹专用状态明确显示不适用的仓室／工艺，并提示核心原库存未清空等接管阻塞。已知源工艺缺少核心时明确标出所需核心；尚未完成首次绑定的普通样板显示“待首次执行验证”，不提前假定它属于某一工艺。

运行信息显示本 tick 已用/总加工额度、外部 FE 储能及 ME 实际取电量、单次与批次闪电费用、代偿状态、闪电不足、下一次被动检查和待交付量。普通／扩展仅显示容量区别，不增加 T 级仓室、输入标记、加工进度或分网设置。大目录分页同步，只同步玩家正在查看的必要数据。
