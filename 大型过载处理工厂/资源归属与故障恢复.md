# 大型过载处理工厂资源归属与故障恢复

[文档首页](../README.md) · [工厂设计目录](设计目录.md)

本代在 LT 工厂内部保存有限托管、待输出和退款记录，由专用执行器维护资源的唯一归属。以下是 0t、多网络、扩展样板页和双用途成型必须遵守的恢复要求，不等待下一代通用账本或 ME 输出仓。

## 背压和资源归属

工厂只有有限的待输出、托管和退款记录，不提供无限库存。接收前预留必要空间；网络满、输出未排空或恢复预算耗尽时停止相应新接收。查询、尝试交付或重新加载不能重复生成产物。

持久化至少包括机器/仓室身份、中央核心种类、机器用途和结构版本、真实工艺核心与工艺版本、样板仓容量、真实样板或催化材料、模式与条目选择、供电策略、整机外部 FE 储能、来源绑定的 ME 能量余额、托管材料及来源、已支付成本、待输出/退款的实际剩余量和提交序号。执行缓存是可重建数据，加载后重新校验实际中央方块及苍穹位置条件，不能直接信任保存的用途或输出模板继续生产。

缓存描述、材料托管和已生成产物是三个不同状态。0t 移除了长时间加工进度，但不移除所有权和失败恢复记录。普通执行窗口使用检查溢出的有限整数；外部 `long`/`int` API 按有限窗口调用，不能静默饱和截断数量。


## 结构、卸载与拆装

扫描覆盖所有必需区块，区分结构错误与区块未加载；读取不得隐式加载区块。成员绑定一次性检查独占归属，结构失效立即关闭新接收门禁，稳定时不逐 tick 扫描。

区块卸载暂停工作，保留唯一权威记录。仓室拆除只回收自己的真实样板、催化材料或工艺核心，虚拟处理样板不掉落；已托管或已生成资源不能再次随仓室掉落一份。扩展仓的四页都参与保存和拆除回收，不能只处理当前页；有样板超出 36 槽时不得直接降级覆盖普通仓。控制器与仓室身份需要可恢复且唯一的活动所有权。保留孤立记录的诊断与恢复入口，不静默清理含资源状态。

验收覆盖正常保存/加载和执行异常；Minecraft 的区块、SavedData 与外部网络没有跨文件原子提交，不能声称任意进程崩溃或备份回滚下都能实现端到端 exactly-once。
