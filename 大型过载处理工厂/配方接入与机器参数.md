# 大型过载处理工厂配方接入与机器参数

[文档首页](../README.md) · [工厂设计目录](设计目录.md)

本机向通用框架提交配方来源适配、运行参数与专有成本，使用框架现成的材料分配、样板编译、消耗、调度、产出和恢复能力。

## 配方来源

通过 `OverloadProcessingRecipeCatalog` 读取最终 RecipeManager 中的本体、处理器推导和已适配反应仓目录。来源模组未安装或 KubeJS/数据包已删除的配方不可用，不创建绕过删除的副本，也不改写被借用机器的配方。

适配器将真实输入、确定性产物、FE 工作量、闪电成本与安全批量限制映射为框架 `ProcessingRecipeDescriptor`。现有源格式最多支持 9 种物品输入、1 种输入流体和 1 种输出流体；通用仓室能保存多种流体不改变这一来源限制。

样板真伪、正整数倍率、标签/组件匹配、副产物、歧义选择和重载后快照规则全部使用[框架配方编译](../通用多方块框架/加工/配方描述与样板编译.md)，不另建 `FactoryPatternCompiler` 或专用材料分配器。

## 运行参数

| 参数 | 本机默认值 |
| --- | --- |
| 基础操作份数 / 封顶 | 1 / 65,536 |
| 基础配方通道 / 封顶 | 1 / 64 |
| 批量 FE | `E_recipe × 源配方执行次数` |
| 最少有效加工时间 | 4 tick |
| AE 任务 / 持续生产新接收权重 | 3:1，空闲额度可借用 |
| 未完成批次 / 交付与退款事务 / 每批键数 | 256 / 1,024 / 64 |
| 持续生产输出优先级 | ME 输出仓优先，普通输出仓兜底 |
| 成品库存目标 | 可选；按网络成品、未交付产物和在制品去重计算 |

仓室等级和能力贡献复用框架默认规格，安装上限见[仓室接入方案](仓室接入方案.md)。调度、FE 进度和背压由框架按本机参数执行。

旧单方块工厂继续使用原有非线性并行公式。本机选用框架线性策略，不调用依赖旧库存最大并行值的 `computeTotalEnergy`。这是本机平衡配置，不改配方材料与产出。

例如单次配方 400,000 FE、1 个高压闪电，256 次共需 102,400,000 FE 和 256 个高压闪电。单个持续供能 T2 仓至少 13 tick，T4 仓仍受 4 tick 下限限制；同时运行其他配方还需分享功率。

## 专有成本适配

LT 闪电适配器将需求编入框架额外成本描述，通过已绑定 ME 端点直接扣费。框架安排支付时点、保存支付结果、调用补偿并恢复批次；本机定义网络来源、闪电等级和 4:1 替代规则，见[闪电运行成本设计](闪电运行成本设计.md)。

## 框架接入方式

工厂注册定义、配方适配、策略参数和成本适配器后，实例化框架运行时。通用 ME 样板总成发布框架编译的有效样板；普通与 ME 输入仓参与框架取料；框架执行消耗和加工，再按任务来源回流或路由持续生产产物。工厂不另建调度器、资源账本或状态恢复实现。
