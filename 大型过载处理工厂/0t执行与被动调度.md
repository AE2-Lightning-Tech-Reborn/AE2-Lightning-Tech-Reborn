# 大型过载处理工厂 0t 执行与被动调度

[文档首页](../README.md) · [工厂设计目录](设计目录.md)

本机在 LT 工厂执行器中实现同步 0t 和按仓互斥的按单／被动模式。以下时序、材料所有权、费用账本和失败恢复均属于本代工厂的实现要求，不依赖下一代通用加工运行时。

## 按单执行与 0t 回传

1. CPU 向仓室派发实际材料，仓室检查成形、当前发布状态、模式、工艺授权和全厂剩余额度；未绑定的源工艺在匹配后再次核实。
2. 缓存过期或实际材料签名未命中时，在此次执行内初始化。无合法配方、预算不足或条件不符时拒收对应份数。
3. 确定实际接受数量，预留必要输出/恢复空间，结算费用，提交材料消耗及产物所有权。
4. 支持内部回传接口时，将已经生成的产物交给本次派发的 `OutputSink`，等 CPU 完成待收产物等派发记账后，在同 tick 消费回传；不在记账前直接向网络投递。
5. 没有内部接收器时保留产物，待派发返回后通过接单仓正常网络路径交付；不保证普通 CPU 的后续链路也能在同 tick 完成。

复用 `DeferredCraftingProvider` 的同步执行与延后收货契约，不直接照搬只支持分子装配样板的矩阵配方执行器。Sink 和 JobView 仅在本次调用内借用，不能保存在仓室或故障记录中。Sink 拒绝时仍由工厂持有产物，不能因此退回已经消耗的原料。

批量 API 的 `oneCopyTemplate` 是只读的单份材料模板，返回未接受份数。例如提供 100 份、实际接受 24 份，返回 76；CPU 负责这 76 份材料的返还，仓室不能再退款一次。成功接受以后的异常进入恢复，不伪装成拒收；无法确定所有权时停止该路径并保留诊断，避免重发。


## 被动取料、初始化与执行

被动模式只考虑本仓已启用的实体或虚拟样板。按输入声明合并本轮涉及的材料键，同一网络内兼容权限的同键查询可复用；不先复制整个网络库存，也不为每张样板重新枚举主网。

1. 有轮询或唤醒额度时，轮询待检查条目，按样板的输入要求形成无重复占用的取料计划。标签/模糊输入仅在样板允许的候选范围内解析，不枚举全网物品组合。
2. 首次执行或缓存失效时，优先取得一份样板所需的真实材料，登记到本仓的有界托管区；材料没有取得齐全则不初始化成功、不扣加工费。
3. 用实际材料进入[首次执行初始化](配方接入与机器参数.md)的完整匹配，生成或复用执行描述并验证工艺授权。水晶条目还要校验对应常驻材料。
4. 初始化成功后，可以在剩余预算内继续取得其他份数并扩大本批；第一份已经取得的材料计入本批，不能重复提取或重复扣费。后续份数出现不同实际材料签名时分别验证，不能沿用不适用的输出。
5. 全部条件满足后结算成本，0t 完成，将产物交回本仓网络。按实际插入量扣除待输出剩余量。
6. 初始化失败、取料不足或尚未提交时无法支付成本，按已取得资源的来源退款。返还失败的余量保留恢复，不能销毁或把退款记录当作新投入。

按单模式的拒收材料由 CPU 管理；被动模式的已提取材料由仓室管理。两条路径共用匹配和加工执行器，但不得共用一个不区分来源的退款入口。

库存查询和 `SIMULATE` 不预留材料。多个配方竞争同一资源时必须用实际无重叠分配和实际提取结果结算；同网多个仓看到的是同一库存，不能把数量相加。部分成功必须逐键记账，不能假定模拟成功意味着所有实际提取都会成功。


## 被动调度：100 tick 周期与完成唤醒

被动检查周期为 **100 个服务器 tick**，正常 20 TPS 下约 5 秒。它是缺料或空闲时的保底探测周期，不是每一批加工必须等待的时长。

- 每台工厂的周期错开相位；同一工厂合并本次到期的被动仓，避免同服每 5 秒集中访问网络。
- 合成提交、费用/产物记账和本次回传或回网处理结束后，额外标记一次待检查。正常接单与被动加工的完成都可唤醒同厂被动调度。
- 同一轮多份完成、多个仓同时完成以及定时事件撞上完成事件，都合并成一个待检查标记，不为每件产物创建事件。
- 完成回调只入队，不能直接递归调用搜索、提取或发配。调度器在本 tick 剩余预算内继续；份数、调用或工作额度耗尽则排到下一 tick。
- 缺料、确定无可执行配方或失败取料不生成“完成”唤醒；没有新的完成事件时，等待下一次 100 tick 周期。模式、样板、材料、工艺授权或网络状态变化可主动标脏并唤醒。
- 重试待输出和退款也使用有界调度；成功交付改变了可用库存或解除阻塞时可合并唤醒，失败不能形成忙循环。
- 暂停、区块卸载或服务器卡顿不积累可补发的历史轮询次数，恢复时只安排一次检查。

公平轮询保存仓间和仓内游标，先给其他就绪仓执行机会，再回到当前仓的下一批；缺料条目跳过后让其他条目获得机会。大量样板跨 tick 分段检查，不能每个完成事件都重新遍历全部槽位。互相转化的样板可能跨 tick 持续加工并耗能；UI 明示被动模式会持续执行已启用条目，不把同 tick 递归循环作为实现方式。
