# 协同调度仓设计

[文档首页](../../README.md) · [仓室目录](仓室目录.md)

协同调度仓提高整机同时运行的不同配方数量，不增加操作份数或 FE 吞吐。

| 项目 | 设计 |
| --- | --- |
| ID 后缀 | `scheduling_hatch_t1...t4` |
| 规格 | T1–T4 |
| 安装数量 | 由接入机器的结构定义与计数约束决定 |

## 等级与能力

以下为默认设计参数。

| 等级 | 增加的不同配方通道 |
| --- | ---: |
| T1 | 1 |
| T2 | 3 |
| T3 | 7 |
| T4 | 15 |

各等级提供上表中的通道贡献。所属机器决定基础通道数和总上限，多个仓室线性叠加后受机器上限约束；汇总公式见[能力汇总与机器接入](能力汇总与机器接入.md#汇总与预算)。

通道按源配方 ID 与执行指纹分组，不按样板槽数计算。同一配方的多个订单可共享一个配方通道，但仍分别保存材料、任务来源、批次和产物，不能把不同 CPU 的所有权混在一起。

安装更多调度仓不会增加 `P` 或 FE/t。以 `P = 1,024`、`R = 4` 为例，可给四种配方各分配 256 份，也可分配为 512、256、128、128；不能给四种配方各分配 1,024 份。只有一种配方繁忙时，它可以使用全部空余份数。

## 界面与拆换

界面显示本仓贡献通道。移除后降低新接收能力，保留已有记录；重成形后超出当前通道数量的配方暂停轮候，不作废已接收材料。
