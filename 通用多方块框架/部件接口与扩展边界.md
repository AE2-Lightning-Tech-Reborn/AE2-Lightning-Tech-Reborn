# 分层接口与机器接入边界

[文档首页](../README.md) · [框架设计总览](设计总览.md)

框架负责完整机器的搭建、仓室、处理、消耗和恢复；接入机器用定义与适配器描述差异，不复制通用执行器。

## 框架内部协作

| 模块 | 对外提供 | 依赖的输入 |
| --- | --- | --- |
| 结构与建造 | 格子表、预览、自动搭建、扫描、绑定与有效性 | 机器模板、尺寸与部件白名单 |
| 通用仓室 | 来源视图、实际库存操作、FE、能力贡献、样板与网络端点 | 有效绑定与玩家配置 |
| 配方编译 | `ProcessingRecipeDescriptor`、真实匹配、材料分配和样板倍率 | 机器注册的有效配方来源适配 |
| 加工运行时 | 接单、托管、调度、进度、产出、退款与交付 | 执行描述、部件能力和机器策略参数 |
| 成本执行 | FE 扣除、可选成本支付、补偿与已支付记录 | 配方成本描述与专有成本适配器 |
| 持久化 | 机器运行实例、批次与资源恢复、仓室独立库存 | 稳定身份、版本与实际操作结果 |

通用样板总成直接桥接框架加工运行时，不要求每台机器另外实现 provider、材料接收器或输出队列。仓室、加工和持久化之间通过稳定身份及最小契约协作，不传递内部可变集群或 CPU 引用。

## 接入机器提交的内容

| 接入项 | 机器负责声明 | 框架负责执行 |
| --- | --- | --- |
| 结构定义 | 默认/允许预设、外壳/核心映射、扩展模板及部件数量 | 预设解析、形状生成、尺寸/锚点校验、搭建、扫描和绑定 |
| 配方适配 | 来源 ID/版本、完整原料与产物、工作量和批量限制 | 材料分配、样板编译、真实派发校验与执行快照 |
| 运行参数 | 基础份数/通道、封顶、最短时间、权重和预算 | 能力汇总、公平调度、FE 支付与加工计时 |
| 额外成本 | 类型、单位、可用性查询和实际扣除/返还策略 | 调用时点、批次支付状态、部分失败补偿与恢复 |
| 展示扩展 | 名称、资源模型、专有状态和可选界面项 | 通用控制器页面、仓室菜单、同步和权限检查 |

机器可注册专用部件或成本扩展，但不能绕过资源守恒、绑定有效性与运行账本。扩展应通过明确契约接入，不直接生成产物或修改框架的已支付数量。

## 规则与配置的归属

凡是更换机器名称、配方来源或资源类型后仍需执行的机制，都在框架维护：预设解析、部件服务、材料分配、任务接收、资源交接、成本支付、来源恢复、输出路由、目标控制、验证与性能预算。具体机器只记录选用的规则、数值、角色映射、适配器语义和展示资源。

通用执行逻辑在一个专题维护，机器文档通过链接引用。机器专有参数可以明确列值，但不复制算法、通用验收矩阵或存档恢复流程。新增扩展若其他机器也需要，先完善框架契约，再由机器注册配置。

## 服务访问与失效

角色必须来自结构定义与注册行为，不因方块暴露 capability 就自动合法。解除绑定、旋转、拆换和卸载使旧接口失效；外部持有的包装器也在每次调用检查身份和结构版本。

普通仓室独立库存与框架任务托管严格区分。解体后仍可通过有效独立接口访问仓室自己的库存；托管材料、运行进度和待交付资源由框架运行时保留，不能再次由仓室取走。

## 处理与消耗边界

物料匹配、取得、消费、FE 扣除、计时、产物生成和实际交付由框架统一执行。机器的配方适配只描述真实关系；运行成本适配只操作自身来源并返回准确结果，框架据此提交或恢复批次状态。

专有成本缺省为空。LT 闪电属于大型工厂的成本适配，通用仓室和核心协议不导入 `LightningKey`。更多规则见[运行成本与消耗接口](加工/运行成本与消耗接口.md)和[资源契约](加工/资源契约.md)。
