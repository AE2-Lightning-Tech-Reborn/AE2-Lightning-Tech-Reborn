# 运行成本与消耗接口

[文档首页](../../README.md) · [框架设计总览](../设计总览.md)

框架统一执行普通物料消耗、FE 进度支付和可选专有成本，并保存真实结果。机器提供配方参数与成本适配器；通用运行时负责顺序、批次状态、部分失败、补偿和恢复。

## 消耗分类

| 消耗 | 来源与时点 | 框架记录 |
| --- | --- | --- |
| 普通配方物料 | AE 任务由 CPU 交付；持续生产按计划从普通/ME 输入来源实际提取，开工时消费托管物料 | 原始键、数量、来源、未消费量与已消费标记 |
| FE 工作量 | 加工 tick 从能源仓按可用储量与吞吐扣除 | 本批目标 FE、实际已支付 FE 与有效加工时间 |
| 可选专有成本 | 在开工条件准备完毕后，经适配器实际支付；没有成本时跳过 | 成本类型、来源、实际键/数量、支付状态与补偿记录 |

同一项投入只走一种归属路径，不同时算作样板物料和额外成本。查询、模拟与可见库存均不等于支付或资源预留。

## 成本适配器契约

| 职责 | 约束 |
| --- | --- |
| 描述成本 | 将源配方的额外要求编入确定性执行快照，声明数量单位、倍率和可批量边界 |
| 检查可用性 | 只作接收规模提示，不持久化跨 tick 的模拟承诺 |
| 实际支付 | 通过有效来源执行扣除，准确返回实际取得量，保留来源与恢复所需身份 |
| 部分失败补偿 | 按实际成功取得的部分原路返还；无法返还时保留有界恢复记录，不启动加工 |
| 正常恢复 | 已支付不重扣，未完成补偿先恢复，不盲目改道到其他来源 |

首期额外成本按批次开工支付，FE 按进度支付。其他扣费时点需要扩展明确的执行契约，不能由适配器在任意回调中重复扣费。

## 具体消耗计划与来源

适配器把成本展开为实际键、数量、单位和来源要求，框架按具体计划执行并逐项记账。同一种成本可由多个键共同满足；替代比例、等级与启用条件由具体适配器声明，通用执行器不硬编码资源名称。

任何一项支付不足都不能使批次开工，已经成功的部分先按记录补偿；补偿未完成前不重复支付该批。网络端点发现、权限、同网去重、来源选择和恢复使用[通用网络服务](网络连接与权限设计.md#运行成本端点与来源选择)，适配器只声明来源偏好和资源语义。

成本可以在接收前查询用于限制规模，但仅在开工时实际支付；不为闲置机器囤积成本，也不把恢复账本作为可由玩家配置的补料仓。FE、AE 待机功耗和额外成本各自计费，额外成本不能再通过样板普通物料重复收取。

## 开工提交顺序

1. 编译并冻结执行描述，检查结构、能力、资源分配和输出/恢复记录空间。
2. 实际接管普通物料，建立 `Admitted` 批次及资源来源；未完整取得时退款或恢复，不凭查询量接管。
3. 调用额外成本适配器真实支付。任一部分失败则停留在 `Admitted`，先执行补偿，不产生 FE 进度。
4. 成本齐备后，在同一服务器线程记录已支付状态和已消费物料，进入 `Running`。
5. 按实际 FE 扣除推进工作量，满足能量与有效时间后一次性生成待交付产物。

服务器线程顺序提交保证正常运行内的一致性，不代表跨区块、网络和 SavedData 的磁盘原子事务。持久化保证边界见[资源契约](资源契约.md#持久化保证的范围)。

## 暂停、取消与恢复

缺电只暂停进度，不退回已消费材料。未开工可以按托管账本退款；开工后不能同时保留进度并全额返还投入。已完整支付的额外成本不会在重载、断网或产物回流时再次扣除。

尚未支付成本时等待所需来源；已经完整支付的批次在结构和剩余 FE 条件满足时可继续运行，交付失败则等待。没有额外成本的配方完全跳过相应来源要求。

成本来源暂不可用时等待原路恢复，不能把它当作免费成本或删除记录。运行成本不受仓室自动拉取/输出开关控制；由框架运行策略、结构有效性及适配器条件决定是否继续。

## 工厂扩展示例

LT 闪电适配器负责闪电等级、网络来源与 4:1 补足规则，通用运行时负责支付记录与批次恢复。具体规则见[大型工厂闪电运行成本设计](../../大型过载处理工厂/闪电运行成本设计.md)。其他机器可不声明额外成本或提供自己的适配器。
