# 通用框架验收与性能预算

[文档首页](../README.md) · [框架实施路线](实施与验收.md)

本文件是所有接入机器共用的验收与性能规则。先用两种不同结构、配方和成本配置验证框架，再由具体机器补充自身配置与适配验收；通用能力不能只在大型工厂环境中验证。

## 结构内核验收场景

| 领域 | 成功条件 |
| --- | --- |
| 预设复用 | 三种默认预设由框架维护，两种机器引用相同预设时复用形状与定位；默认项、范围交集、步长和锚点校验正确 |
| 预设恢复 | 切换、内容变更或删除时记录版本、重新验证并保留任务，不静默换用其他结构 |
| 定义一致性 | 扫描、预览、材料清单与自动搭建使用同一格子表，空气与忽略位不计材料；合法部件不能替换固定棱角、模块或空气位，错误能定位 |
| 定义校验 | 未知角色、重复位置、层尺寸错误、无效锚点和不可满足约束能在加载时定位 |
| 尺寸与朝向 | 两种定义入口和四个水平朝向共用扫描逻辑；可变尺寸有界，偶数尺寸定位一致 |
| 替换规则 | 只允许声明的部件替换，不因暴露 capability 自动取得合法角色 |
| 区块 | 枚举覆盖的全部必需区块，中间区块未加载返回 `INCOMPLETE`，不能只查四角或隐式加载；恢复后库存和任务仍保留 |
| 所有权 | 相交结构只有一个能取得冲突成员，提交失败不留下半绑定 |
| 失效 | 结构变化和区块卸载立即关闭旧服务入口，缓存包装器拒绝过期写入 |
| 生命周期 | 暂停、重新检查、成形和确认解体可区分；框架事件不直接清理机器资源 |
| 调度 | 稳定结构不逐 tick 扫描，同 tick 变更合并，未成形结构的有界候选区域能够被唤醒 |
| 独立性 | Thunderbolt 单独验证时不依赖 LT 工厂类、资源、闪电或 AE 合成 |

## 通用部件验收场景

| 领域 | 成功条件 |
| --- | --- |
| 统一仓室 | 四类输入输出仓可保存物品、流体及合法自定义 AEKey，物品/流体适配视图共享同一库存；未知加工类型不被误用 |
| 普通仓容量 | T1–T4 按键名额与每键数量正确限额，混合键共用名额；升级保留库存与配置，降级容量不足时拒绝 |
| ME 无限容量 | 超过 128 个标记/过滤项或 `Long.MAX_VALUE` 的单键数量仍精确保存，分页不构成容量限制 |
| 拉取模式 | 只补充启用标记到目标量，关闭补料后仍可消费真实库存 |
| 库存模式 | 无标记不提供物料，同网同键去重；匹配不扣料，实际取料按权限与返回量记账 |
| 模式切换 | 余料返还受阻时不启用重复网络视图，删除标记不删资源或退款记录 |
| 输出 | 关闭普通/ME 输出开关后保留资源，外部仍可合法提取；重新开启只交付剩余量，不影响样板回流或运行成本 |
| 数量窗口 | ME 大整数库存跨 `long`/`int` 窗口累计、部分插入、存档恢复和退款保持精确，窗口不构成仓室容量限制 |
| FE | 多方向和重复调用共享单仓吞吐限额，模拟不占额度，混装按各仓实际能力汇总且不复制储能；需要 FE 的批次未取得 FE 时无进度 |
| 并行与调度 | 等级贡献正确，机器基础值和封顶可不同，多总成共享同一预算 |
| 样板总成 | 只发布本总成经框架验证的样板，100 份接受 24 份返回 76，不修改借用模板；单份回退与批量结果一致 |
| 网络回流 | 完成产物晚于 CPU 记账交付；换网、原端口缺失或归属不明时暂停恢复 |
| 持久化 | 库存、样板、能源与任务各有唯一持有者；部分传输、拆换和正常存档恢复不丢失或复制 |
| 多机器复用 | 同一通用部件服务两种测试机器，不通过具体工厂类提供库存、FE 或样板接口 |

## 完整加工链路验收

| 场景 | 成功条件 |
| --- | --- |
| 搭建 | 同一定义驱动预览、材料清单、搭建和扫描；保留合法带库存部件，失败不丢料或复制方块 |
| 配方 | 重叠 Ingredient、不同组件、标签和多来源物料正确分配；伪造产物、漏副产物和错误倍率被拒绝 |
| 物料 | 模拟不是预留，按真实取得量托管；部分取得失败只退实际持有量，不重复退款 |
| 消耗 | FE 按实际工作量扣除；额外成本可包含多个实际键，部分支付失败先补偿，不进入运行或重复扣费 |
| 成本网络 | 无额外成本不额外要求联网；仅总成联网也可提供合法成本端点，同网多端口去重，不暗中合并多网库存；待补偿记录只走原来源 |
| 调度 | 多总成与同 tick 多 CPU 共用 `P`；`R=4` 时第五种配方轮候，总份数与 FE 仍共享；大订单和持续生产并存时小订单持续得到服务 |
| 产出 | 满足 FE 和最短有效时间后才生成产物；回网晚于 CPU 记账，部分交付只扣真实数量 |
| 背压 | 普通仓满或事务预算耗尽时等待；ME 输出仓断网、目标网络满或自动输出关闭时保留并可继续接收，过滤不匹配和真实接口错误仍正确处理 |
| 路由与目标 | 每键优先级、同优先级轮询和部分转移不复制产物；成品目标计入网络、未回网实物和在制品且不重复计算；样板任务不受持续生产目标或路由改道 |
| 重载与改配置 | 配方删除后不接新单，已接收快照可完成；清除标记不删资源、降容量不截断库存、改尺寸不自动拆方块 |
| 重入与异常 | 存储回调重入、同 tick 反复查询容量、接收后异常均不造成重复退款、扣费或产出 |
| 取消与恢复 | 未开工可退托管资源，已消费不全额退款；断网、卸载、拆装和正常存档恢复保持唯一归属 |
| 多机器 | 两种不同结构/配方/成本配置使用同一个运行时完成建造到产出的全链路，无 LT 工厂实现依赖 |

## 性能预算

性能设计应先限制可计量的工作量，再通过真实服务器调参：

- 成形扫描只在相关变化后执行，同 tick 多次变化合并；全服务器设扫描工作预算，超出预算排队且保持接单门禁关闭。
- 活动加工复杂度随批次数与资源键数增长，不为 65,536 份批量创建 65,536 个对象或逐份执行确定性配方。
- 配方编译按目录版本缓存，派发只验证实际输入签名；库存变化触发重匹配，空闲时退避。
- ME 拉取和输出按端口公平分摊每 tick 调用额度；库存模式只关注已标记键并复用网格变更版本，不每 tick 扫全网或为每个仓复制全网清单。同网同键查询可复用，实际提取仍核验实时条件。
- ME 仓动态键表、标记和库存采用分页遍历、增量同步与分段保存；单 tick 未处理完的工作延后，不以固定页数或缓存条目数限制实际容量。保存只在状态变化时标脏，不每 tick 深拷贝全量库存。
- 测试记录多机器数量、模板体积、活动配方数、批次数、资源键数、TPS/MSPT 和 GC。性能数值必须来自该环境实测，不能用微基准结果代替整机验证。

## 验收顺序与记录

结构、建造、部件、加工、消耗、交付和恢复全部通过后，才接入具体机器。测试定义应覆盖无额外成本和多键成本两类场景；专有资源名称与换算比例不写入通用用例。

按 AE 样板任务、持续生产、两者混合和大量机器同服记录配置、规模及测量结果。具体机器可使用同一套用例验证接入，但只在其文档维护配方来源、装配、参数和专有成本的差异。
