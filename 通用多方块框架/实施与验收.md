# 通用框架实施与验收

[文档首页](../README.md) · [框架设计总览](设计总览.md)

框架完成结构、搭建、部件、加工、消耗与恢复的完整验收后，再接入具体机器。结构测试不依赖 AE；部件与加工测试使用真实所需接口、测试配方和可控成本适配器，不依赖 LT 工厂类或闪电类型。

## 结构内核实施顺序

在 Thunderbolt 实现并独立验证：

1. `StructureDefinition`、局部坐标变换、固定/可替换/空气/忽略角色与数量约束。
2. 通用预设目录、长方体生成器、尺寸/锚点策略与分层模板加载，解析机器引用后输出统一格子表和材料需求视图。
3. `StructureScanner` 的有效/无效/区块未加载结果与定位诊断。
4. `StructureIndex` 的成员独占、位置/区块变更索引和原子绑定。
5. `StructureRuntime` 生命周期、立即失效门禁、合并复扫与有界调度。
6. 以两个小型测试定义验证框架不依赖 LT 工厂类、资源、闪电或 AE 合成。

结构内核门槛：不同定义与朝向都能使用同一套扫描和绑定逻辑；未加载区块不引发世界加载；稳定结构不逐 tick 扫描；两个控制器不能共享成员。达到这些条件后进入通用部件实现与验收。

## 通用部件实施顺序

1. 统一仓室角色、稳定部件身份、绑定校验、库存权威归属与回收协议。
2. 普通输入/输出仓的 AEKey 库存、T1–T4 容量、类型适配和自动物流。
3. 能源接入仓的独立 FE、同 tick 吞吐计数；并行/调度仓的等级贡献与能力汇总。
4. ME 输入/输出仓的标记、过滤、拉取/库存模式、大整数库存、网络权限及部分传输恢复。
5. ME 样板总成的库存、GUI、共用 provider 与机器加工接口，复用 TB 批量协议。
6. 部件菜单、分页/增量同步、分段保存、拆换恢复，以及与结构生命周期的联动。

部件门槛：同一组通用仓室能够接入两个不同测试机器定义，库存和任务资源不重复，服务不依赖某个工厂类、配方目录或闪电类型。

## 加工、消耗与恢复实施顺序

1. 实现 `ProcessingRecipeDescriptor`、目录版本、`ResourceInputView` 与无重复占用的材料分配器。
2. 实现 `ProcessingPatternCompiler`、样板真实性/倍率校验、快照及重载失效。
3. 实现 `ProcessingBatch` 和统一运行账本，处理托管、真实取料、部分失败与退款。
4. 实现 `MachineEnergyPool`、`ProcessingScheduler`、FE 工作量、有效时间、操作份数和配方通道预算。
5. 实现可选运行成本调用、真实支付、补偿与已支付恢复，缺省无专有成本。
6. 实现持续生产及 AE 样板流程、产物账本、部分交付、原端口回流和输出背压。
7. 接入机器 UUID 持久化、唯一运行实例、正常保存/加载、拆换与孤立记录恢复。
8. 完成通用搭建/维护页面、仓室 GUI、分页与增量同步。

## 独立测试定义

使用两个小型定义覆盖参数化生成与分层模板两种入口，组合固定部件、可替换位、内部模块、空气位和忽略位。具体方块由测试环境提供，不以大型工厂的仓室清单作为唯一测试素材。

## 验收与阶段门槛

统一的结构、部件、加工、消耗、路由、恢复及性能规则集中在[框架验收与性能预算](验收与性能预算.md)。以上实施阶段都必须在两种独立测试机器中通过对应验收，然后按[大型工厂接入路线](../大型过载处理工厂/实施与验收/实施路线.md)验证具体配置与适配器。
