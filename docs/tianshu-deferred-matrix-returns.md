# 天枢 CPU 与矩阵的同 tick 内部回传

天枢 CPU 派发矩阵配方时，矩阵将已生成的产物交给本次派发的内部队列。
CPU 完成任务扣数、待收产物登记、闭环种子记账和预算扣减后，再消费队列；
随后继续选取当前 tick 的就绪任务。回传处理通过外层循环推进，不递归调用调度器。

批量入口沿用 Thunderbolt 的 `BatchJobView`，LT 的视图额外实现
`DeferredCraftingProvider.Job`。普通派发使用同一个内部 provider 的带接收器重载。
无需修改 Thunderbolt 公共接口。矩阵不给接收器时仍使用原有 5t 缓冲。

接收器仅在本次派发期间有效，不能由机器保存。入队成功后 CPU 获得这份产物的
所有权，矩阵不会再持久化或再次交付它；拒绝入队则仍由矩阵缓冲负责。
入队内容复制进独立计数器，不保留会被重绑定的任务视图。

收货复用 CPU 原有严格匹配、过载输出、催化剂、闭环种子与请求方交付逻辑。
即使派发恰好耗尽本 tick 的预算，已生成产物仍在这次派发末尾处理。
CPU 成功派发量、份数预算、矩阵供电、热量和每 tick 调用上限继续生效。

最终产物及取消后余货若不能立即放入网络，会保存在独立的
`deferredDeliveryRemainders` 库存。该库存参与 CPU 保活、NBT 保存和拆除掉落，
不充当新的合成材料；回网时阻止本 CPU 再次认领，防止重复推进完成量。

## 验证

Java 21 环境执行：

```sh
./gradlew test build --offline --no-daemon
./gradlew runDeferredReturnsGameTestServer -Pae2ltDeferredReturnsTestsOnly=true --offline --no-daemon
```

专用 GameTest 使用真实 AE2 配方、变换后的派发代码，以及生产代码的矩阵端口、
控制器、核心和天枢 CPU。测试替换结构发现、能量供应和磁盘，避免依赖已有存档。

- 原木 → 木板 → 木棍 → 梯子的三层批量合成在一次调度、同一游戏 tick 完成。
- 同一配方链走普通逐次派发时也能同 tick 完成，正确扣除 8 次派发预算。
- 最后一次预算耗尽后仍收到中间产物，下一 tick 可继续。
- 共享催化剂在同 tick 的两个闭环批次之间返回，最终只退还一份种子。
- 需要具体种子键记账的单份派发路径，同 tick 连续执行 4 次并正确退还种子。
- 存储满时最终产物与余料存档恢复后各交付一次，CPU 排空后释放。
- 存储回调尝试重新执行 CPU 时被拒绝，不递归派发或重复交付。

单元回归另覆盖旧任务回传、回调内取消、相同产物的重复认领、内部队列关闭、
计数溢出拒绝、矩阵缓冲隔离，以及吞吐/能量预算。

Reborn alpha 基线为 `538f9523`。验证使用 Reborn Thunderbolt 2.0.0 发布制品
（SHA-256：`13430a9a6bbb189375b199d5c27d5568fc57975630ef149854d9645c9d4af7f8`）。
本机同坐标的旧 Thunderbolt 缓存仍使用旧包结构，因此通过临时 Gradle 初始化脚本
指定已验证的依赖仓库；项目依赖坐标保持不变。

7 项 GameTest 全部通过，构建成功。同时补齐现有菜单测试清单中的采矿工厂项。
