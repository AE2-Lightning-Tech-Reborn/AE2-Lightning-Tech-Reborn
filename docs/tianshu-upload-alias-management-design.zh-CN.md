# 天枢样板编码终端：上传别名管理界面设计

状态：设计稿，尚未实现。日期：2026-10-27。

## 1. 设计结论

新增「上传别名管理」子界面，集中管理玩家自己保存的别名。主界面只呈现「配方来源 → 上传别名」，提供搜索、新增、编辑、逐条删除；匹配检查放入编辑页，作为辅助信息。

主要入口放在现有上传目标选择界面的左侧工具栏；另在天枢终端设置中添加文字入口，允许没有已编码样板时直接整理别名。界面沿用 AE2 的子界面、输入框、按钮、滚动条和返回标签。背景先采用纯色面板，不做装饰纹理。

本设计只管理用户保存的别名，不引入机器地址绑定、路由优先级、网络共享或自动分流。

## 2. 已有行为与边界

以下结论来自当前仓库实现：

| 项目 | 现状 | 本次设计的处理 |
| --- | --- | --- |
| 数据 | `tianshuTerminal.uploadAliases` 保存 `source=alias` 字符串列表 | 继续兼容现有配置，不另建一份数据 |
| 来源 | 优先使用配方类型 ID；无实际配方对象时可使用 JEI/EMI 分类 ID | 显示为「配方来源」，完整 ID 可查看、复制 |
| 关系 | 一个来源对应一个自定义别名；多个来源可以使用同一别名 | 每个来源一行，同名别名不合并 |
| 保存 | `setUploadAlias` 替换同来源记录并保存客户端配置 | 新界面和上传界面共用保存逻辑 |
| 删除 | `removeUploadAliases(alias)` 会删除所有使用该别名的来源记录 | 普通删除改为按来源精确删除，不能复用当前批量删除语义 |
| 默认候选 | 来源 ID、模组通配词、配方查看器提供的候选词等 | 不列入已保存清单；仅在编辑页提供建议 |
| 快速绑定 | 上传目标列表 `Shift + 右键` 可生成并保存别名 | 保留快捷操作，同时提供可发现的文字按钮 |
| 手动放入样板 | 无法可靠恢复原配方来源，当前来源和别名留空 | 不把产物名称或产物 ID 冒充配方来源 |
| 生效范围 | 客户端配置，不按存档、服务器或 ME 网络隔离 | 明示「保存在本机，跨存档／服务器共用」 |

别名是供应器分组的筛选词，不是某个物理机器的唯一标识。分组显示名支持大小写不敏感的包含匹配及现有通配规则；图标注册 ID 使用完整值通配匹配。拼音匹配沿用现有兼容层，不额外承诺新的搜索能力。

本界面服务于加工类样板的供应器选择。合成类、闭环和寰宇熔炉等现有上传路径不改动。

## 3. 玩家最需要的操作

| 玩家需求 | 交互 |
| --- | --- |
| 忘记自己给哪些配方设置过别名 | 打开即显示全部已保存记录和总数 |
| 记录多，想找某个模组或机器名 | 一个搜索框同时搜索来源 ID、可用的来源显示名、别名 |
| 机器改名，原别名失效 | 选中记录，编辑别名，保存后立即用于后续上传 |
| 不小心绑定错了 | 按来源删除这一条，其他使用同名别名的记录不受影响 |
| 想恢复自动推荐 | 删除自定义记录，之后重新使用现有默认候选逻辑 |
| 想提前配置 | 从终端设置进入，手动新增来源和别名，无需先编码样板 |
| 不知道筛选词该怎么写 | 从当前网络目标选择一个分组，填入建议别名，并显示匹配数量 |

首版不加入批量删除、全部清空、导入导出、启停开关、排序优先级和服务器配置档。它们不属于日常逐条管理的必要操作，会增加界面和数据模型负担。

## 4. 入口与返回

### 4.1 上传目标选择界面：主要入口

- 左侧工具栏新增「管理上传别名」按钮，紧邻现有保存别名按钮。
- 将现有按别名批量删除的工具栏按钮替换为管理入口，避免继续暴露易误删的动作。
- 保留快速保存，将提示文字明确为「保存当前别名」；同来源已有其他值时显示旧值和新值，再确认替换。
- 管理页打开时定位当前来源的记录，但不自动加搜索过滤，玩家仍能看到完整列表。
- 如果当前来源尚未保存，显示非阻塞提示「当前来源尚未设置别名」，「新增」默认带入当前来源和当前筛选词。
- 返回上传页时保留原搜索、候选与滚动状态；若当前来源已修改，刷新为新保存值；若已删除，重新计算默认候选；无关来源的修改不改动当前筛选词。
- 从管理页返回只刷新筛选结果，不因已有的直接上传标记自动提交样板；玩家重新点击上传目标。

### 4.2 天枢终端设置：常驻入口

在样板编码终端的「上传」相关设置附近添加文字按钮「管理上传别名…」。仅在样板编码终端显示，有线与无线终端共用实现。

这个入口不依赖已编码样板，也不要求当前存在配方查看器上下文。打开时显示全部记录，不默认选中第一条，不无意覆盖当前配置。

### 4.3 返回规则

列表页右上角沿用 AE2 返回标签，`Esc` 返回实际进入它的页面；编辑页返回列表。共用原终端 menu，不重新打开容器。进入子界面隐藏槽位，离开后恢复父页槽位布局，不丢失编码草稿和库存状态。

## 5. 主界面：简单的别名清单

### 5.1 布局

建议标准面板宽 **304 GUI px**、高 **220 GUI px**；这些是 Minecraft GUI 逻辑像素，不是屏幕物理像素。左右内边距 8 px，顶部标题、搜索、表头依次排列，中间列表占据主要空间。

```text
┌ 上传别名管理                         [返回] ┐
│ [搜索来源或别名…                      ×]   │
│ 配方来源                 上传别名           │
│ mekanism:crushing         粉碎工厂           │
│ mekanism:enriching        富集工厂           │
│ example:pressing          金属压机           │
│ …                                     ▐   │
│                                            │
│ 共 12 条 · 保存在本机                       │
│ [新增] [编辑] [删除]                        │
└────────────────────────────────────────────┘
```

示例 ID 和别名仅为布局示意，不表示已检测到这些模组或现有配置。

- 两列按约 55%／45% 分配；来源 ID 是稳定信息，有可靠本地化名称时可在提示中补充，不杜撰分类名称。
- 列表行高 20 px，默认显示约 6 行；选中整行有浅蓝灰底，悬停仅做轻微提亮。
- 不在每行放编辑、删除图标，不加状态徽章或常驻匹配计数，减少视觉噪声。
- 长文本裁切加省略号，悬停显示完整来源和别名；不横向滚动。
- 列表按来源 ID 大小写不敏感排序；搜索中显示「找到 3 条 / 共 12 条」。清空搜索保留选中记录，必要时滚动定位。
- 无选择时禁用「编辑」「删除」，禁用原因通过提示说明；双击一行等同编辑。

### 5.2 空状态与操作反馈

- 无记录：「还没有保存的上传别名」，下方短提示「可在上传时保存，或点击新增」。
- 搜索无结果：「没有找到匹配的别名」，提供清空搜索操作。
- 保存后选中新记录并滚动可见；若新值不符合当前搜索，清空搜索并说明已清空以显示保存结果。
- 删除后优先选中相邻记录；列表为空时回到空状态。
- 成功反馈放在底部状态行，例如「已保存」「已删除 1 条」，不刷聊天栏。
- 本机共用范围的完整说明放在底部文字提示中；不要误导为当前服务器专属设置。

## 6. 新增／编辑页

沿用同宽纯色面板，以单栏表单呈现，不挤入主列表的侧栏。

```text
┌ 编辑上传别名                         [返回] ┐
│ 配方来源                                   │
│ [mekanism:crushing                     ]    │
│ 上传别名                               [?] │
│ [粉碎工厂                              ]    │
│ [使用当前来源] [从目标选择…]                │
│                                            │
│ 当前网络：匹配 1 个分组             [刷新] │
│ 匹配检查只作参考，保存不会上传样板。          │
│                                            │
│ [取消]                              [保存] │
└────────────────────────────────────────────┘
```

### 6.1 输入与保存

- 「配方来源」和「上传别名」都有固定标签，不只依赖 placeholder。两个字段均可编辑，以便修复手填错误。
- 来源帮助：「配方类型或配方查看器分类，不是产物 ID」。来源按现有规则去除首尾空白并转小写；别名去除首尾空白，保留展示大小写。
- 两个字段不能为空；来源不能包含 `=`，来源和别名各最多 256 字符，序列化后的 `source=alias` 不超过现有配置的 512 字符上限。错误紧贴字段显示，保存禁用。
- 来源不能仅因当前模组未加载或注册表未查到而被拒绝：旧存档、其他服务器和查看器分类仍可能需要它。来源不支持通配匹配，提示明确区分别名中的通配词。
- 编辑时仅改别名：覆盖原来源记录；修改来源：原记录迁移到新来源，一次性写入配置，避免残留旧条目。
- 新增或迁移来源撞到已有记录时，展示被替换的来源与旧别名，选择「替换」或「取消」；不静默覆盖。内容完全相同则提示「该别名已存在」。
- 保存成功后才更新列表；写入失败保留草稿并提示重试，不能提前显示成功。
- 有未保存修改时，`Esc`、返回或取消提示「放弃修改 / 继续编辑」；无修改直接返回。`Ctrl + S` 保存；输入框内 `Enter` 不触发删除或上传。

### 6.2 降低手填成本

- 「使用当前来源」只在存在有效配方上下文时可用，仅填来源，不自动保存；无上下文时禁用并解释获取方式。
- 「从目标选择…」打开选择模式的供应器列表。点击分组仅将建议别名带回表单，绝不发送上传请求。
- 建议值沿用 `preferredAlias`：自定义分组名称优先，否则优先使用图标注册 ID。返回表单后仍需点击保存。
- 已有默认候选可通过小型候选按钮查看并填入，候选本身不持久化。滚轮切换可作为快捷方式，但不能成为唯一可发现入口。
- 输入框保留普通选择、复制、粘贴；明确的清空按钮比仅靠右键清空更易发现。

### 6.3 匹配检查：从属信息

编辑时使用同一份目标快照和 `TianshuUploadTargetMatcher` 本地计算，输入变化不逐字请求服务器。打开和手动刷新时请求目标，刷新中保留原数据并标为旧快照；未收到响应与确实零匹配必须区分。

| 状态 | 展示 |
| --- | --- |
| 尚未拿到目标快照 | 「正在获取当前网络目标…」；失败／超时后显示「暂时无法检查」及重试 |
| 0 个匹配分组 | 「当前网络无匹配目标」，允许保存 |
| 1 个匹配分组 | 「匹配 1 个分组」，允许展开分组名 |
| 多个匹配分组 | 「匹配 N 个分组，直接上传时需要选择」，允许保存 |

没有可验证的加工样板时只检查分组匹配，**不得显示“已满”或“可以上传”**：当前服务端会在没有样板时把可用槽位数返回为 0，不能把这个 0 当作真实满载。

只有携带当前加工样板的有效快照，才附带「约 N 个可用槽位」或「当前样板暂无可用槽位」。多个分组即使只有一个有空位，仍然是多匹配，不能建议静默选择它。实际上传始终由服务端重新检查。

匹配预览不要求全部记录常驻计算，不把无匹配判为无效配置，也不因连接到另一服务器自动删除记录。

## 7. 删除语义

选择记录后点「删除」，弹出小型确认层，明确显示来源和别名：

> 删除这条上传别名？删除后该来源将使用默认候选。其他来源不受影响。

按钮为「取消」「删除」。默认焦点在取消；不提供默认 `Delete` 快捷删除，不用别名值作为删除键。清理绑定不移除任何已上传样板，也不修改机器。

## 8. 视觉规范与占位图

- 整体采用 AE2 常见的浅灰面板与深色文字，不使用大面积品牌色、渐变、阴影、插画或装饰边栏。
- 暂定背景 `#C6C6C6`，列表／输入区 `#E2E2E2`，选中行 `#AFC4D4`，边线 `#565656`，主文字 `#252525`。实际文字优先沿用 AE2 palette。
- 所有背景区域均为纯色；状态不只靠颜色表达，必须配文字。
- 间距采用 4／8 px；按钮高度约 18～20 px；最终以 AE2 控件实际尺寸和字体测量结果校准。
- 标准宽 304 px；当可用 GUI 宽度不足时缩到可用宽度并保留边距。窄于 280 px 时改为两行记录（来源在上、别名在下），底部三个按钮按可用宽度排列。
- 高度随窗口裁切列表可见行数，允许低于 6 行；标题、搜索和底部操作固定，不能照搬现有选择器“至少 6 行”导致小窗口溢出。极小尺寸必要时表单内容滚动，返回与保存仍可达。
- 本次附带 [纯色布局示意图](design/tianshu-upload-alias-management.svg)，用于审阅信息层级和布局，不是 Minecraft 实机截图，也不是最终 GUI 纹理。
- 实现阶段用 `GuiGraphics.fill` 绘制占位背景，面板绘制与控件坐标分离；后续替换背景纹理不改交互逻辑。

## 9. AE2 复用与实现落点

| 部分 | 推荐方式 | 已有依据 |
| --- | --- | --- |
| 页面生命周期 | `AESubScreen`，共享父 menu，显式管理返回路径 | 上传选择页、终端设置页 |
| 搜索与表单 | `AETextField`，沿用焦点、输入、提示机制 | 上传选择页已有两个输入框 |
| 标准操作 | `AE2Button` / `widgets.addButton` | 天枢设置页已有使用 |
| 工具栏入口 | `IconButton`，选现有语义合适的图标并加 tooltip | 上传选择页已有 `AliasActionButton` |
| 返回标签 | `TabButton(Icon.BACK, …)` | 现有两个子界面 |
| 列表滚动 | `Scrollbar.SMALL` | 上传选择页 |
| 字体与颜色 | Minecraft font、AE2 `PaletteColor` | 上传选择页绘制逻辑 |
| 列表行 | 少量自绘文本、纯色选中框与命中检测 | 现有上传选择页同样自绘行 |
| 样式 | 新增 `assets/ae2/screens/tianshu_upload_aliases.json` 等布局资源 | 现有布局实际位于 `assets/ae2/screens/` |

不为本功能另造通用 UI 框架，也不把所有操作塞进现有 190 px 宽的上传选择器。具体管理图标在实现时从项目所用 AE2 版本核实，本文不预设不存在的图标常量。

建议代码拆分：

1. `TianshuUploadAliasManagementScreen`：搜索、选择、列表、新增／编辑／删除入口。
2. `TianshuUploadAliasEditScreen`：编辑草稿、冲突确认、可选匹配检查。
3. `AE2LTClientConfig`：增加读取记录快照、按来源删除、原子替换／迁移能力。所有入口使用同一数据操作层。
4. 目标列表抽取可复用的只读选择部分，或增加明确的“选择别名”模式；不能直接复用上传点击回调。

管理页有两种父页面，不应把父类型写死成编码终端主屏。具体泛型组织应在实现时结合 `AESubScreen` 的父屏约束处理，保留准确返回路径与输入状态。

旧配置存在重复来源时，维持当前“第一条生效”的读取语义，显示重复提示；用户编辑／删除该来源时统一处理该来源的重复项。解析失败的原始项不能因保存其他条目被静默丢弃。取消操作不写配置。

## 10. 验收清单

- 从上传选择页和终端设置均能进入，有线／无线版本入口一致；无样板时仍能管理。
- 主清单只显示用户保存的别名，不掺入自动候选或机器列表。
- 搜索、新增、改别名、改来源、冲突替换、取消和重启后的持久化均符合预期。
- 两个来源共用同一别名时，删除一条不会影响另一条。
- 空白、过长、包含分隔符的来源、最大序列化长度、重复旧记录与配置写入失败均有明确处理。
- 手动插入样板时不编造来源；没有样板时不误报满载。
- 0／1／多个匹配分组、唯一分组无槽位、多匹配仅一个可写等情况保持既有上传判定语义。
- 从目标选择别名、保存别名、返回上传页都不会意外上传或消耗样板。
- 返回后终端槽位、配方草稿、搜索与必要的滚动位置正确恢复，菜单失效时不会继续操作旧网络。
- 窄窗口、高 GUI 缩放、长中文名称、长 ID、空列表和大量记录下无重叠，键盘焦点与滚动可用。
- 后续替换背景只改绘制／纹理，不改变布局数据与业务状态。
