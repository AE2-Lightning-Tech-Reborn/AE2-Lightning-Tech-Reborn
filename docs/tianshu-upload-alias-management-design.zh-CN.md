# 天枢上传别名与撤回：实现说明

本分支基于 Reborn alpha，实现稿取代原先包含匹配检查及分组选择子页的设计。

## 操作与配置

- 编写／编码按钮左键编码、右键撤回、Shift + 右键打开管理。
- 管理页保留搜索、新增、编辑、按来源删除，以及剪贴板导入／导出。
- 编辑页只保留来源和别名，JEI／EMI 的 + 可以填写来源。
- 自动上传模式位于前一级天枢设置页，管理页仅管理别名记录。
- 自动上传三档：OFF / SAVED_ALIAS / ANY_MATCH，默认 OFF；配置属于本机玩家，适用于所有天枢终端。
- SAVED_ALIAS 只使用明确保存的来源映射。ANY_MATCH 仍优先保存值，否则使用查看器机器注册 ID；无机器信息才采用旧候选规则。
- 多机器候选合并计算匹配分组；全满分组也参与歧义判断。唯一且可写才自动提交。
- 来源键仍是原生配方类型，显示模型无原生配方时使用查看器分类 ID。机器 ID 仅是候选，不改变现有配置键。
- 手动放入的样板没有可靠的配方来源，保持来源为空，不把产物 ID 当成来源。

## 剪贴板

格式为 `format: ae2lt-upload-aliases`、`version: 1`、`aliases: [{source, alias}]` 的 JSON。最多 1024 条、1,048,576 个字符。完整校验后一次合并保存；拒绝重复来源、无效类型或超长内容。冲突确认后覆盖，保留未涉及记录和模式。导出不包含自动上传开关。

## 多玩家与撤回

服务端每个菜单只记录最后一次成功上传。供应器记录原网络、目标对象、槽号、槽内物品对象身份及内容快照；撤回取出真实物品，不通过客户端数据生成物品。闭环记录原端口、仓库和实际加入的 payload 对象，按对象身份删除后归还已支付的样板。

撤回要求原网络有效、目标可访问、编码槽为空、对象和内容均未改变。另一个玩家换入完全相同样板也不能被旧记录取走。记录在菜单关闭时清除，失败不会退回更早的上传。成功仅归还已编码样板，不退款额外空白样板。

加工上传目标列表携带版本，并绑定原成品的对象及内容快照，过期请求重放会拒绝。自动上传还绑定当前玩家最近的编码确认，防止列表生成之前成品已被其他玩家替换；手动选择使用当前快照。服务端再次验证目标分组和空槽。网络操作在服务端主线程排队，客户端配置互不共享。

## 验证入口

`scripts/tianshu-upload-workflow-test.init.gradle` 提供聚焦 JUnit、真实 GameTest 和原生客户端探针。可选 `-PuploadWorkflowThunderboltJar=<本地 TB jar>` 用于离线依赖。客户端使用独立 `build/tianshu-upload-alias-client` 存档，需要 `-Pae2ltAliasProbeWorldSeed=<QA level.dat>`；`-Pae2ltJeiOnlyForTest=true` 切换 JEI-only 配置。探针结束恢复客户端别名、开关与剪贴板。

验证覆盖导入失败不写入、覆盖确认、三档切换、JEI 机器 ID、多个机器匹配拒绝自动上传、有线／无线成品槽返回，以及双玩家记录隔离、共享槽替换、相同样板替换和重复撤回。

## 本次验收结果

- 46 项聚焦 JUnit／源码契约检查通过。
- 4 项真实 GameTest 通过：有线／无线满目标保留成品、双玩家上传与撤回、真实闭环仓库撤回。
- JEI-only 与 EMI 两种客户端配置均通过有线、无线终端流程：实际配方转移带入 `minecraft:furnace`，无保存别名时不误用别名档，保存别名及任意匹配档均完成真实自动上传；导入导出、覆盖确认、撤回和返回路径通过。
- 原生截图检查了管理与编辑页，修复 AE2 长输入框背景截断，并检查窄窗口底部按钮和列表互不覆盖。
- 上传快照数据包使用 `upload-target-2` 协议版本；客户端和服务端需要一同更新。
