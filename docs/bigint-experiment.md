# BigInteger 精确数量链路

该功能最初在 `experiment/bigint-pipeline-20260918` 开发，现已整合到 `main`。

## 使用方式

同时安装配套构建的 Thunderbolt Core 和 AE2LT，客户端与服务端保持一致。精确报表包包含“仅预览”标记，需要两端一起更新。
普通 AE2 终端，以及天枢合成/样板终端，共用原来的“数量 → 确认/CPU 选择 → 合成状态”流程。
入口只依赖 AE2 的 `IActionHost` 网络接口，不要求终端特化接口。没有多维天枢时仍可计算和显示；执行精确订单需要在线且空闲的多维天枢。
网络中的普通样板供应器、long 批量供应器和多维矩阵可以参与同一订单。无限存储元件用于保存超过 long 的库存。
没有新的大数合成页面、模式开关或额外入口。数量框保留单位、表达式、加减按钮、Enter、Shift 自动开始和 `=` 补足库存语义。

数量超过原生输入范围时，菜单通过专用数量包传输 BigInteger；普通请求继续走已有规划器。
普通请求产生精确超量预览时，确认菜单自动尝试精确规划，并按可用 CPU 决定是否能开始。
确认页使用已有 AE2LT 报表，任务出现在原 CPU 列表，可选择、暂停和取消。
天枢终端的库存格显示紧凑数量，悬浮提示保留精确数量。确认页和 CPU 状态页保留精确合成数量。

## 数据与执行

- 保留原 `MEStorage` 的 long ABI，新增 `BigMEStorage`，无限存储元件启用精确账本。
- long 与 BigInteger 操作同一份库存；旧双 long 存档可以升级。普通存储以单次 long 调用桥接，不循环执行海量分块调用。
- Native 网络与驱动器继续使用存储优先级、过滤和挂载状态；旧 long 聚合视图饱和投影，避免多块无限盘汇总变成负数。
- 按目标从 AE2 合成服务捕获相关样板；矩阵配方校验真实装配，普通配方记录具体输入、声明产物和容器返回。V2 产生候选，独立执行前缀证书复核。
- 有种子的环可压缩成重复块。计划和存档不展开每次合成；混合块按执行游标逐步发配，每 tick 的工作量有界。
- 下单后材料归 CPU 独占托管。纯矩阵块保留压缩原子结算；混合块中的矩阵步骤仍经过真实装配验证。
- 普通供应器调用原 `pushPattern`，每次一份；批量供应器调用 long `pushBatch`，支持原有适配器、准备阶段、部分接单和明确共享的催化剂。每次输入/产物总量也限制在 long 内，剩余订单保持 BigInteger。
- 调用前登记待回料和扣除托管输入；明确拒绝的部分退款。只有实际回料进入原 AE2 CPU 插入路径，才计入完成，不根据计时器生成外部机器产物。
- 已接单量、待回料、重复块游标一起保存，恢复不会重发已接受的工作。供应器在所有权不确定时抛异常会暂停任务，避免重试复制材料。
- 取消退还当前托管库存；已交给外部机器的材料不重复退款，随后回料通过原路径进入网络。网络无空间/断开时保留未返还余额。
- 控制器 UUID 运行存档保存计划、游标、暂停状态、待返还材料；控制器掉落仍沿用既有身份保存机制。

## 实验边界

这不是整个 AE2 生态的任意精度迁移：普通 CPU、外部机器、维护规则等现有 long API 保持原合同。
外部机器遵循其原生单次/long 接单与回料合同；数量很大的普通单次供应器仍需相应执行时间。仅提供自定义私有调度、无法按原生样板接口执行的路线，需要相应适配。不会因为供应器没有 BigInteger API 而拒绝整个计划。
每个控制器目前同时持有一份精确任务；普通时间轮任务列表保持原类型。

规划总预算 3 秒。当前捕获最多 16384 个具体配方，单输入最多 32 个候选，每样板最多 64 个具体组合，证书搜索最多 200000 次配方探测。
数量设置 16384 bit 的资源保护（约 4933 位十进制）；不是 long 上限，但也不是无资源上限。
精确确认报表继承 Thunderbolt 的 8192 条目 / 512 KiB 保护；极端图和极端数量的组合尚未做分页传输。
未通过复核、超预算或无法捕获的路线不会开放开始按钮；它们仍可能产生保守缺料或未完成结果。

## 验证

- TB：独立随机执行对照、巨大种子环、25 层十倍链、容器/催化剂、伪造证书、500 bit 随机存储、旧存档升级、压缩与重复加载、网络金额编码和显示。
- LT：矩阵/合成核心/天枢现有回归；真实 NeoForge GameTest 验证网络和 DriveWatcher Mixin、两块无限盘、真实配方、原 CPU 提交接口、断开配方/存储、NBT 快照恢复、完成与取消退款。
- 混合路径：真实成型矩阵与多维天枢接入普通 `ICraftingProvider`，通过原生网络回料完成；等待回料时保存恢复，核对输入、中间物、主产物和副产物守恒。
- 大数兼容：`10^100` 订单交给普通单次供应器；long 批量部分接单/同步回料；超过 `Long.MAX_VALUE` 的订单分批完成；拒绝退款、异常暂停、能量和准备阶段限额；精确报表通过原生确认包往返。
- 既有真实客户端探针在天枢有线/无线样板终端分别测试 `10^100 + 12345` 原料、原数量按钮、返回后精确数量保留、手动选择 CPU、原确认页精确材料、开始、原 CPU 状态页、取消、退款和库存同步。
- NBT 快照恢复测试不等同于整服进程重启测试。

运行（Java 21）：

```sh
# Thunderbolt 仓库，先发布本地依赖
./gradlew test --tests '*Big*Test' --tests '*ExactAmountCodecTest' publishToMavenLocal
# AE2LT 仓库，单元测试使用完整依赖
./gradlew test --tests '*Matrix*Test' --tests '*CraftingCore*Test' --tests '*Tianshu*Test'
# 游戏测试使用隔离配置，不要将该配置套在上面的单元测试上
./gradlew runGameTestServer -I scripts/bigint-gametest.init.gradle
# 原界面客户端探针，需隔离存档 build/bigint-client-probe/saves/BigIntProbe
./gradlew runClient -I scripts/bigint-client-probe.init.gradle
```

客户端探针会重建隔离存档中的测试结构，只能对测试存档运行。截图写入该游戏目录的 `screenshots/native-big-*.png`。
