# BigInteger 精确数量链路

该功能最初在 `experiment/bigint-pipeline-20260918` 开发，现已整合到 `main`。

## 使用方式

同时安装配套构建的 Thunderbolt Core 和 AE2LT，客户端与服务端保持一致。TB 需要包含 `BigLongSlice` 的混合供应器支持（Reborn 提交 `4b59ae7` 或包含它的后续版本），不能只凭相同的 beta 版本号替换旧缓存 JAR。精确报表包包含“仅预览”标记，需要两端一起更新。
普通 AE2 终端，以及天枢合成/样板终端，共用原来的“数量 → 确认/CPU 选择 → 合成状态”流程。
入口只依赖 AE2 的 `IActionHost` 网络接口，不要求终端特化接口。没有多维天枢时仍可计算和显示；执行精确订单需要在线且空闲的多维天枢。
网络中的普通样板供应器、long 批量供应器和多维矩阵可以参与同一订单。无限存储元件用于保存超过 long 的库存。
没有新的大数合成页面、模式开关或额外入口。数量框保留单位、表达式、加减按钮、Enter、Shift 自动开始和 `=` 补足库存语义。

数量超过原生输入范围时，菜单通过专用数量包传输 BigInteger；普通请求继续走已有规划器。
普通请求产生精确超量预览时，确认菜单自动尝试精确规划，并按可用 CPU 决定是否能开始。
确认页使用已有 AE2LT 报表，任务出现在原 CPU 列表，可选择、暂停和取消。
天枢终端的库存格显示紧凑数量，悬浮提示保留精确数量。确认页和 CPU 状态页保留精确合成数量。

## 数据与执行

- 保留原 `MEStorage` 的 long ABI，新增 `BigMEStorage`，无限存储元件启用精确账本。
- long 与 BigInteger 操作同一份库存；旧双 long 存档可以升级。普通存储以单次 long 调用桥接，不循环执行海量分块调用。
- Native 网络与驱动器继续使用存储优先级、过滤和挂载状态；旧 long 聚合视图饱和投影，避免多块无限盘汇总变成负数。
- 按目标从 AE2 合成服务捕获相关样板；矩阵配方校验真实装配，普通配方记录具体输入、声明产物和容器返回。V2 产生候选，独立执行前缀证书复核。
- 有种子的环可压缩成重复块。计划和存档不展开每次合成；混合块按执行游标逐步发配，每 tick 的工作量有界。
- 下单后材料归 CPU 独占托管。纯矩阵块保留压缩原子结算；混合块中的矩阵步骤仍经过真实装配验证。
- 普通供应器调用原 `pushPattern`，每次一份；批量供应器调用 long `pushBatch`，支持原有适配器、准备阶段、部分接单和明确共享的催化剂。每次输入/产物总量也限制在 long 内，剩余订单保持 BigInteger。
- 调用前登记待回料和扣除托管输入；明确拒绝的部分退款。只有实际回料进入原 AE2 CPU 插入路径，才计入完成，不根据计时器生成外部机器产物。
- 已接单量、待回料、重复块游标一起保存，恢复不会重发已接受的工作。供应器在所有权不确定时抛异常会暂停任务，避免重试复制材料。
- 取消退还当前托管库存；已交给外部机器的材料不重复退款，随后回料通过原路径进入网络。网络无空间/断开时保留未返还余额。
- 控制器 UUID 运行存档保存计划、游标、暂停状态、待返还材料；控制器掉落仍沿用既有身份保存机制。

## 同 tick 推进与普通 CPU 的共享行为

纯矩阵压缩块、混合计划中的矩阵步骤在验证和接单后立即结算，不再人为等待 5 tick；随后可以在同一个 tick 继续下游步骤并交付成品。
普通单次/long 批量供应器支持 `DeferredCraftingProvider` 时，精确 CPU 与普通时间轮 CPU 共用派发事务：先接收真实产物到队列，结清本次发配的接单量和退款，再回收产物并继续下游。
取消期间已经移交的真实产物仍保留在托管库存中退回，不能因为任务已经取消而丢弃；异步机器仍按自己的实际回料推进。

精确服务按宿主 CPU 核心档位的派发额度限制每游戏 tick 的发配尝试，复用 `CpuInternalCoreProfile.successfulDispatchesPerTick()`，最大 16384。当前精确订单要求多维核心，因此实际额度为 16384。同 tick 重入或重复调用不会刷新预算，完成最后一次发配后仍可当 tick 交付成品。
旧存档已经记录的 `readyAt` 批次会按原截止时间完成一次；新的矩阵发配不再写入延迟。
网络无法接受成品时仍保留余额并间隔 5 tick 重试，此间隔只用于库存背压。

两个执行器共享发配/回收合同，不直接继承普通版的库存实现。普通 CPU 的 `ListCraftingInventory`、`KeyCounter` 和任务计数使用 long，精确 CPU 需要独立的 BigInteger 托管账本、待回料和压缩执行游标；继承普通实现无法让这些字段自动获得任意精度。

共用组件位于 `crafting.runtime`：

- `CraftingDispatch` 管理一次派发的回料所有权与结算边界。后端完成接单、退款、待回料和预算记账后确认结算，关闭事务才交付队列；未完成结算时只保留实际产物，不推进任务。关闭后不能再次入队或重复交付。普通供应器使用原生 long 队列，万象精确回调使用 BigInteger 队列。
- `CraftingTickBudget` 按物理 tick 累计工作量。同一实例在同 tick 再访问不会补充额度。普通池共享成功派发次数上限，各虚拟 CPU 保留份数上限；精确版按实际发配尝试计费，精确份数不转换成 long 预算。普通版原有探测公式 `min(max(1024, 2 × 本次派发额度), 262144)` 保持不变。
- `CraftingExecutionState` 管理执行与交付期间的防重入。允许外层执行过程中交付产物，但回调不能递归运行调度器或重复排空交付库存；退出路径用 `finally` 释放状态。

共用层不持有 CPU 库存、任务计数或计划游标。普通时间轮继续负责任务唤醒、种子与请求方逻辑，精确版继续负责压缩块推进和任意精度账本；取消与存档仍由各自后端维护。

## 候选索引与缺料唤醒

参考 nutant233（nutant / mutan）的 [RecipeSearch](https://github.com/GregTech-Odyssey/RecipeSearch) / Fast Recipe Search 及 GTO 的集成方式，独立实现“缩小候选后完整校验”。没有引入外部 trie 库，也没有复制上游源码；署名见 `THIRD_PARTY_NOTICES.md` 和 JAR 内的 `META-INF/recipesearch-attribution.txt`。

精确 CPU 只为当前查询过的输出建立样板定义索引，候选顺序与原服务一致。通过 TB 的供应器变更 revision 失效，包括同一 tick 多次增删；没有该 revision 能力时回退原查询。缓存至多 64 个输出目录，不枚举整个 ME 网络。矩阵样板仓在内容变更时刷新自己的定义索引，批量编辑尚未通知端口时也立即失效。查到候选后仍逐次验证真实输入、容器返回、产物、结构及接单条件，不能把索引命中当作配方有效。

普通时间轮将可枚举输入折叠为忽略 NBT/components 的物品或流体候选族，按候选族登记缺料与唤醒。每个 CPU 共享候选族的实际库存总量，只在这一族库存变化时失效，不维护每个样板的 NBT 匹配表。原生禁止替代的精确输入仍可直接读取精确键数量。候选统计只证明“即使放宽匹配也不够一份”；它不调用 `isValid`、提取材料或查询供应器，也不取代原生输入匹配与材料分配。

AE2 原生合成/处理样板及其 LT 过载包装具有稳定候选定义，包括开启物品和流体替代、ID_ONLY 的情况，缺料后只由相关库存变化唤醒。不同候选可合计数量，新 NBT 变体也能触发检查；部分回料不足时继续停放。库存通知覆盖正常回料、拒单退款和库存清空。未知自定义候选保留原 4/32 tick 期限，但缺料时只刷新候选元数据和粗数量；候选列表变更后可用已经持有的材料恢复。候选可能足量时继续执行原生动态条件检查；条件不满足、机器忙碌、拒单和供能不足仍沿用原冷却，无需等待新回料。优先级、原始候选顺序和调度份数定义不变。

精确版按当前步骤的具体材料登记缺口，相关真实回料或退款使其重检；无关回料不解锁。缺料状态是可重建的派生数据，不写入存档。等待材料及普通供应器发配不再发现矩阵目标。纯矩阵压缩块的前缀证书、原子结算和计划顺序保持原定义。

## 新版万象合金炉

可选接入 [Useless Mod 1.21.1-2.4.6](https://github.com/SorrowMist/UselessMod/releases/tag/1.21.1-2.4.6) 的公开 `api.crafting.bigint` 接口。通过网络中的公开目标发现多方块万象，以单份材料原型和精确份数进行 `admit → commit`，遵守机器返回的容量、能量、结构、背压和共享输入限制。
没有该模组或缺少这套 API 的旧版仍使用原单次/long 路径。仅在需要发配受支持的外部样板时发现目标，不为纯矩阵订单或等待回料的步骤遍历网络。

真正入账发生在机器的 `claimOutputs` 移交回调；`onBatchOutputs`、`onBatchFinished` 只是通知，不能再次生成库存。同步移交先暂存到本次发配结束，异步移交按任务 UUID 找到恢复后的 CPU 账本。明确拒绝会退款，所有权不确定的异常会暂停任务，取消后拒绝认领旧任务的机器产物。

万象自身仍在其正常机器 tick 刷新产物；这个兼容层不会强制调用机器 tick，也不承诺万象整条加工链 0t。
默认配置下，万象的材料窗口和运行时预算仍可能限制每批数量；启用其 `ae_unlimited_bigint_parallelism` 配置时，本层可传递完整精确数量。共享催化剂等不支持的配方仍回落原路径。
2.4.6 的机器 NBT 保存待回料账本，但没有保存 CPU 回调绑定：CPU 自身快照恢复可继续批量认领，整服或机器重新加载后则由万象按原生 long 回网。数量保持精确，但极大批次在这种恢复场景下可能交付很慢；此处不将 CPU 快照测试当作整服重启验证。

## 实验边界

这不是整个 AE2 生态的任意精度迁移：普通 CPU、外部机器、维护规则等现有 long API 保持原合同。
外部机器遵循其公开接单与回料合同；没有精确批量接口的普通单次供应器仍需相应执行时间。仅提供自定义私有调度、无法按原生样板接口执行的路线，需要相应适配。不会因为供应器没有 BigInteger API 而拒绝整个计划。
每个控制器目前同时持有一份精确任务；普通时间轮任务列表保持原类型。

规划总预算 3 秒。当前捕获最多 16384 个具体配方，单输入最多 32 个候选，每样板最多 64 个具体组合，证书搜索最多 200000 次配方探测。
数量设置 16384 bit 的资源保护（约 4933 位十进制）；不是 long 上限，但也不是无资源上限。
精确确认报表继承 Thunderbolt 的 8192 条目 / 512 KiB 保护；极端图和极端数量的组合尚未做分页传输。
未通过复核、超预算或无法捕获的路线不会开放开始按钮；它们仍可能产生保守缺料或未完成结果。

## 验证

- TB：独立随机执行对照、巨大种子环、25 层十倍链、容器/催化剂、伪造证书、500 bit 随机存储、旧存档升级、压缩与重复加载、网络金额编码和显示。
- LT：矩阵/合成核心/天枢现有回归；真实 NeoForge GameTest 验证网络和 DriveWatcher Mixin、两块无限盘、真实配方、原 CPU 提交接口、断开配方/存储、NBT 快照恢复、完成与取消退款。
- 混合路径：真实成型矩阵与多维天枢接入普通 `ICraftingProvider`，通过原生网络回料完成；等待回料时保存恢复，核对输入、中间物、主产物和副产物守恒。
- 大数兼容：`10^100` 订单交给普通单次供应器；long 批量部分接单/同步回料；超过 `Long.MAX_VALUE` 的订单分批完成；拒绝退款、异常暂停、能量和准备阶段限额；精确报表通过原生确认包往返。
- 0t：真实成型多维矩阵和多维天枢，将 `7 × 10^100` 原木经木板、木棍三级链在一次 tick 调用内完成为 `24 × 10^100` 梯子；按宿主档位的 16384 次发配预算、同 tick 重入、背压、部分接单和取消回料守恒。
- 共用执行合同：同一组测试分别使用 long 与 `10^100` 回料，验证结算前不交付、异常保留、关闭后不重复交付和回调防重入；普通 CPU 边界测试覆盖多个任务共用物理池、同 tick 重复调用及供应器回调重入，验证不能刷新总派发预算。
- 索引与唤醒：同一目录查询 1000 次只读取一次服务候选，但完整校验逐次执行；同 tick 供应器增删及矩阵批量编辑立即失效。1000 个等待样板共用一次候选族库存读取，无关物品变化不使其失效，新 NBT 变体与库存清空会刷新。原生全替代与 ID_ONLY 任务缺料连续 40 tick 不再探测，无关/不足回料不派发，足量回料或退款立即唤醒。未知输入的候选列表与动态条件在没有回料时改变，也能恢复；忙碌、供能和拒单恢复无需材料返回。精确执行器同样覆盖相关回料、部分回料与无关回料。
- 万象：安装官方 2.4.6 JAR 的公开 API 合同测试覆盖 `10^100` 份接单、同步与异步移交、CPU 快照恢复、通知不重复计数、拒绝退款和异常暂停；另用真实成型有用线圈万象及真实 AE 网络，分别执行 AE2 合成样板和万象编码样板，验证超过 long 的接单和机器自然 tick 回料，并遵守其默认容量限制。
- 既有真实客户端探针在天枢有线/无线样板终端分别测试 `10^100 + 12345` 原料、原数量按钮、返回后精确数量保留、手动选择 CPU、原确认页精确材料、开始、原 CPU 状态页、取消、退款和库存同步。
- NBT 快照恢复测试不等同于整服进程重启测试。

```sh

./gradlew test --tests '*Matrix*Test' --tests '*CraftingCore*Test' --tests '*Tianshu*Test'

./gradlew test --tests '*CraftingExecutionContractTest' --tests '*TimeWheelDispatchBoundaryTest'
# 游戏测试使用隔离配置，不要将该配置套在上面的单元测试上
./gradlew runGameTestServer -I scripts/bigint-gametest.init.gradle
```
