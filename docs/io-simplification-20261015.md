# 接口与供应器精简，2026-10-15

基线为 Reborn `origin/alpha` 的 `1e7686ed4468ae2b855654edb0b13d37af0c56b9`。保留自适应重试、正常/快速模式、逐样板公平性、溢出所有权、卸载连接和自动回收语义。

## 生产改动

* 无线供应器用一个就绪队列替代两个互斥队列，去掉只服务于这两个队列的模式参数、泛型状态接口和重复清空路径。调度模式继续决定单目标或均分投递行为。
* 自动回收复用已发布的不可变连接快照。未变拓扑的同步从 O(N) 扫描、去重和临时分配变成 O(1) 引用比较。换快照时仍做内容比较，保留进行中的轮次；普通六面目标仍按原方式刷新。
* 接口刷新有效连接时将“剔除无效连接”和“构造有效列表”合为一次校验。通过 `ArrayList.removeIf` 批量压缩，避免大量失效连接逐个删除时的最坏 O(N²) 移位；卸载目标继续保留。
* 导出公平计划移到独立的 `InterfaceExportPlan`。成功服务顺序使用数组索引双向链，更新 O(1)、下一轮展开 O(F)，替代时间戳和最坏 O(F²) 插入排序。相同材料的重复配置槽仍共享一轮，进行中的遍历顺序不会被成功回调改变。F 为过滤配置槽数，当前最多 36。

接口主类 3034 → 2803 行，其中主要是职责拆分；计入新增类后，本轮所有改动的生产文件合计 6719 → 6692 行，净减少 27 行。没有把搬走的代码算成删除。复杂调度本体、模式和预算仍保留，尚不是整个 I/O 子系统的重写。

## 调度器单独测量

使用 `ThreadMXBean` 记录当前线程分配，独立 JVM 顺序 A/B/B/A。1024 个固定目标的回收同步预热 5000 次，再测 3 × 10000 次：基线稳定约 65.6 KB/次，候选 0 B/次。该结果仅指未变拓扑同步，不代表整个回收 tick 无分配。

供应器均分基准使用 512 个目标，每轮预热 5000 tick、采样 5000 tick，重复三轮；每个 tick 均断言供给 512 × 512 份。基线与候选的成熟阶段均约 181.72 B/目标访问，样板 `hashCode` 调用均为 0；耗时均在约 0.15–0.16 ms/tick 范围，未见有实际意义的差异。首次较短预热的数值没有用于性能结论。

`scripts/benchmarks/ProviderCostAudit.java` 可用编译后的 main/test 运行类路径直接编译运行。复现旧基线时只需将其 `prepare(targets, tick, false)` 调用改为旧签名 `prepare(targets, tick, false, WirelessDispatchMode.EVEN_DISTRIBUTION)`，并使用基线主类。基准保留逐 tick 工作量断言。

原生对照使用现有 `scripts/interface-export-fairness-test.init.gradle`、`-Pae2ltFairnessBenchmark=true`、`-Pae2ltFairnessKeys=27` 及不同的 `-Pae2ltFairnessRunDirectory`。两侧使用同一个本次 TB `2.0.3-beta2` JAR，隔离 LT 的差异。摘要、实际计数和生产源码 SHA-256 见同名 JSON。
