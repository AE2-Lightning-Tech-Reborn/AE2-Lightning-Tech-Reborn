# 天枢实体样板迁移

Minecraft 1.21.1 / NeoForge。控制器侧栏的“升级样板仓”下面和端口样板管理界面均有“一键迁移样板”。两个入口查看同一控制器的任务与结果。悬停按钮显示扫描计数和未迁移原因，运行时点击“停止迁移”保留已完成的转移。

## 行为

- 移动同网已加载、活动来源的实体编码样板，仅接收 `IMolecularAssemblerSupportedPattern`。不迁移处理样板、闭环样板、解码失败的样板或磁盘内配方。
- 完整物品定义参与去重，忽略数量，保留组件及编码设置。同产物但不同编码设置的样板分别保留。
- 重复样板保持原编码状态，先送 ME 的已确认库存，余量送操作者背包。两处都满则留在源槽。目标满后继续回收重复样板。
- 初始 CPU 忙碌时拒绝启动；运行期间出现合成或已知设备待输出时等待，空闲后继续。关闭菜单继续；操作者离线、目标卸载、结构或网络变化时中止。
- 同一网络互斥；ECO 存在时共享其迁移锁。可选 API 不匹配的来源会跳过并计入未适配统计，ECO 锁本身不可用则拒绝启动。
- 扫描集合冻结在开始时的节点 epoch，新接入设备留到下一次迁移。查询具体机器类及节点，包括已经加载的跨维度节点，不加载新区块。

## 顺序与实现

1. EAE 装配矩阵、EAEP 普通/超级/终极矩阵的底层核心、ECO F 系列实体样板总线。
2. 其他天枢样板仓和原生分子装配器的专用样板槽。
3. 原生及继承 `PatternProviderLogicHost` 的方块/部件供应器。
4. 其他 `PatternContainer`：仅接受能确认原生实体库存且没有未知合成执行服务的来源，其他视图报告未适配。

同层按已有可靠缓存提示、维度、位置、部件面排序，以 32 槽轮询。首先分片检查各层设备的执行状态，不解码样板。发现当前优先层后即可处理其库存，不等待低优先层的库存扫描。EAEP 聚合视图以底层核心去重，只访问实际开放范围；ECO 仅使用 `getPatternSlotInventory()`，不使用隐藏磁盘并追加虚拟行的终端视图。EAE 独立扩展装配器没有实体样板槽，仅检查执行状态。

`MatrixPatternMigration` 持有任务、目标完整仓库索引及结果；`PatternMigrationTransfer` 负责单实体托管、接收回执、原槽回滚。所有操作在服务端线程执行。请求校验菜单、容器编号、位置和访问有效性。样板目录通知按 owner 合并，物理写入与保存标记同步执行。

退款过滤作用于模拟和实际插入。AE2 挂载表记录库存的实际提供者，仅允许元件宿主和明确指向原版箱子、木桶、潜影盒的存储总线；未知提供者和其他落点使用背包兜底。过滤离开调用范围后立即解除。

原槽恢复失败时，未交付的实体保存在控制器恢复槽并终止任务。重新打开授权菜单优先送还，恢复槽未清空前禁止新任务；拆除控制器正常掉落。恢复槽写入 NBT；扫描进度及结果仅在内存中，重启后不续跑。没有跨模组、跨区块崩溃事务日志。

## 预算与验证

默认每网每 tick 2 ms 协作式预算，最多检查 256 槽、主动解码 64 张；服务器共享 4 ms，网络轮转授权。节点发现、目标索引、来源活动检查、转移和批次回调耗时都计入实际切片。第三方同步方法及原生供应器的完整目录刷新不能被安全抢占，可能超预算；状态快照记录 `lastSliceNanos` 和 `budgetHits`。

验证入口：

```powershell
.\gradlew.bat test --tests '*PatternMigrationTest' --console=plain
.\gradlew.bat -Pae2ltPatternMigrationTestsOnly=true runPatternMigrationGameTestServer --console=plain
.\gradlew.bat -Pae2ltPatternMigrationTestsOnly=true runPatternMigrationClient --console=plain
.\gradlew.bat test jar --console=plain
```

先运行服务端测试；客户端入口首次运行时仅复制服务端测试世界的 level.dat，创建独立的 `MigrationQA` 测试世界，不覆盖已有世界。测试代码与空结构模板属于 `jdb`，不进入正式 JAR。混网测试可通过 `-Pae2ltJdbProbeMods` 提供 EAEP、ECO、LDLib2 和磁盘模组 JAR；磁盘模组 0.7.1 测试使用临时参数 `'-Pneo_version=21.1.241' '-Pae2wtlib_version=19.5.1'`，不改变默认依赖。

EAE/EAEP/ECO 测试加载真实 JAR、实际库存与变更回调，使用构造的集群验证适配契约；不等同于这三个模组完整多方块实战验收。十万槽压力场景把原生供应器库存扩大到 100000，包含 99998 个处理样板及两张合成样板，覆盖实际迁移、解码及通知。此极端单宿主场景的原生全量刷新出现过约 0.5–1.83 秒切片，已计入超预算；扫描预算不构成硬性 tick 时间保证。


### 本次验证记录

- 单元与回归：1350 项，零失败、零错误，4 项跳过；迁移专属 17 项全部通过。正式 JAR 的迁移类和 Mixin 完整，测试类与结构模板不在包内。
- 混网服务端：14 项 GameTest 通过；真实 AE2 网络、天枢结构、方块/部件供应器、独立装配器、元件退款、满仓/满背包、恢复 NBT、CPU 暂停/继续、取消、离线、断网、新节点 epoch，以及 EAE、EAEP、ECO、真实磁盘 API。
- 混网运行使用 NeoForge 21.1.241、AE2WTLib 19.5.1、EAE 1.21-2.2.30-neoforge、EAEP 1.6.2、ECO 21.2.1、LDLib2 2.2.40、样板磁盘 0.7.1。
- 最后一轮十万实体槽：1563 个测试 tick，主动移入 2 张、保留 99998 张处理样板；最长切片 571603700 ns，3 次预算命中；其他运行记录到 1830005100 ns。超长切片包含原生供应器重建整个目录，当前实现保持第三方刷新契约。
- 客户端实际菜单与网络包已验证共享结果、GUI 缩放 2/3/4、CPU 等待、停止、恢复送还及关闭菜单后的完成；截图保存在独立运行目录，测试结果文件为 `migration-client-result.txt`。

测试范围没有包含真实玩家多人压力场景、实际跨维度区块卸载或所有外部模组完整结构的实战复现。第一版的恢复槽保障运行中异常回滚，不承诺进程崩溃期间跨区块原子性。
