# 过载水晶催化器设计

状态：设计阶段，尚未实现。目标仓库为 AE2-Lightning-Tech-Reborn，当前基线为 Minecraft 1.21.1。本文记录已确认的产品行为，以及与多方块过载处理工厂合并的候选方案；候选结构、数值与加工订单规则均未定稿，不据此认定已实现新的机器、订单接口或多方块结构。

## 已确认的方向

- 母岩以**生长时不会退化、能够持续产出**为准入条件，普通版、猪咪版及规划中的过载催化都遵守此限制。若 AE2CS 后续加入分级，只接受其中不会退化的无瑕母岩；会退化的其他等级不能作为不消耗的催化剂。当前已核对的无分级、不退化母岩仍可使用。
- 普通水晶催化器继续被动生产。AE2CS 母岩配方基础产量为 8，母岩不消耗；普通版矩阵产量倍率为 8，256 个母岩配合矩阵，每轮产出 16,384 个水晶。
- 猪咪版保持 64 个催化剂、100 个有效游戏刻、无 FE 和无闪电的规则，采用配方基础产量；母岩配方每轮产出 8 个，普通基础产量为 1 的配方仍产出 1 个。
- 普通版输出槽容量为 16,384，猪咪版为 64。旧存档中超过新上限的猪咪产物保留且可取出，输出空间足够前暂停生产，不截断存量。
- 新增的过载版只处理订单，不主动补货，不因催化剂常驻而持续生产。
- 过载版的母岩或其他合法催化剂常驻机器、不消耗，用于决定网络中可以订购的产物。
- 机器自身向 AE2 网络暴露可合成项目，玩家直接在终端下单。无需样板供应器、手工处理样板、订单卡、纸或结晶种子。
- 订单指定多少个最终产物，就生产多少个。不得再次乘以母岩数量、基础产量 8 或矩阵产量倍率。
- 每个订单消耗一次对应配方的流体和闪电，数量不随订单产量增长。普通母岩配方为 1 B 水和 1 道高压闪电；特殊流体配方应使用其对应流体，不能统一替换成水。
- 安装的闪电坍缩矩阵数量决定处理速度，不增加订单产出、不消耗矩阵。
- 过载版目前只记录设计。新增讨论方向为与多方块过载处理工厂二合一，具体方案见下文候选扩展，不开始实现新机器。

### 不退化母岩的核对依据

现有母岩配方依据 AE2CS 公开 1.21.1 的 `bb599989e1074d0165bb079f733e87158d9736a1` 编写。该快照的 11 种 `*_mother_rock` 没有等级区分，均注册为 `CrystalMotherRockBlock`；其 `randomTick` 只更新相邻晶芽/晶簇，不退化或消耗母岩自身，满足当前准入条件。重新查询公开分支及发布记录时，1.21.1 仍为此提交。分级方案可能尚未公开，因此当前以已核对的行为判定，不要求物品名称必须包含“无瑕”。

核对来源：[母岩生长实现](https://github.com/ExtremelyFrozen/AE2-Crystal-Science/blob/bb599989e1074d0165bb079f733e87158d9736a1/src/main/java/io/github/lounode/ae2cs/common/block/CrystalMotherRockBlock.java)及[母岩注册](https://github.com/ExtremelyFrozen/AE2-Crystal-Science/blob/bb599989e1074d0165bb079f733e87158d9736a1/src/main/java/io/github/lounode/ae2cs/common/init/AECSBlocks.java)。这里的“不退化”指自然生长过程，不表示方块无法被玩家或外部机制破坏。

未来适配分级版本时应重新核对行为并精确列出无瑕注册项，不能因为旧物品 ID 仍存在就认定其仍不退化。缺少对应注册项时不加载该适配配方；不猜测 `flawless_` 命名，不使用包含所有母岩的宽泛标签，也不回退匹配会退化的等级。GUI、自动输入、配方匹配及过载订单发布必须使用同一资格条件。已有存档中的不合格母岩应允许取出，但不能继续启动无损生产；在途工作如何暂停与回收另行验证。上述限制针对母岩，不借此更改其他已存在的水晶块配方。

## 玩家流程

1. 放置过载水晶催化器并连接 ME 网络。
2. 放入常驻催化剂（母岩必须不会退化；分级版本只接受无瑕），安装矩阵，并提供所需流体和对应阶级的闪电。
3. 终端显示该催化剂支持的可合成产物。
4. 玩家在终端请求 N 个产物，设备接收并处理对应订单。
5. 设备按矩阵提供的速度生产，将产物送回 AE2 合成系统，累计交付恰好 N 个。
6. 订单完成后停止；保留催化剂、矩阵和未使用的流体。

示例：设备中放有量子母岩，终端请求 100,000 个高纯量子水晶。该订单总产出就是 100,000 个，总开工成本为 1 B 水和 1 道高压闪电；矩阵数量只决定完成这 100,000 个所需的时间。此例不表示已确定实际速度或单订单上限。

常驻母岩的最低数量尚未确定；其数量不得默默变成订单产量或速度的额外倍率。

## 配方与计费

复用现有 `CrystalCatalyzerRecipe` 的催化剂匹配、产物种类、流体及闪电定义。普通版配方的 `output.count` 用于其被动生产，过载订单应使用明确的最终产物数量。

| 配方类别 | 每单流体 | 每单闪电 | 订单产出 |
| --- | --- | --- | --- |
| AE2CS 母岩 | 1,000 mB 水 | 1 道高压闪电 | 请求的最终数量 N |
| 其他耗水水晶 | 配方指定的水量 | 配方指定阶级和数量 | N |
| 特殊流体水晶 | 配方指定流体和数量 | 配方指定阶级和数量 | N |

流体与闪电是已确认的计费项。是否保留普通版的 FE 消耗尚未确定，实现时不能未经确定就把普通版 `energyPerCycle` 按每个产物累计。

建议在订单开始实际生产前一次性结算流体和闪电，并保存“已付费”状态。缺少任一资源时等待，不部分扣费；输出堵塞、区块卸载和存档重载都不能触发重复扣费。流体来源采用机器储罐还是同时允许直接取自 ME 网络，待实现前确定。

## 原生网络订单接口

现有接口可作为接入点：

- AE2 `ICraftingProvider`：设备注册合成服务，并根据当前催化剂暴露虚拟配方。
- TB `IBatchCraftingProvider`：通过批量请求接收数量，避免逐个产物分派。
- TB `BatchJobView.craftingId()`：为已接收工作提供可持久化的合成任务归属。

这些接口可用不等于订单语义已经实现。现有 `pushBatch` 的 `maxCraft` 是本次最多可以接受的配方份数，不保证等于整个终端订单；一次终端下单可能分多次、跨 tick 调用。

因此必须遵守以下约束：

1. 不能把每次 `pushPattern` 或 `pushBatch` 回调都计为一个收费订单，也不能按同 tick 合并来猜测订单边界。
2. 建议以合成任务标识、产物/配方标识和执行设备识别一个生产子订单；同一子订单的后续分派只增加工作量，不重复收取开工费。这个子订单定义仍需在真实 CPU 分派中验证。
3. 跨 CPU 的两个独立订单不得误合并为一笔收费。一个终端任务内部需要多种产物时，如何划分各产物子订单应明确展示。
4. `BatchJobView` 是借用的实时视图，不得保留引用。需要保存的任务标识、数量、配方及费用快照必须复制到机器自己的状态中。
5. 实现前验证原版 AE2 CPU、TB CPU 和天枢 CPU 的订单归属传递；没有稳定任务标识的路径不能假装实现了“每单只收费一次”。
6. 需要证明虚拟配方能够被规划器、终端和递归合成识别。若不把开工资源列为逐份配方输入，界面必须能够说明设备正在等待流体或闪电。

不能简单暴露 `1 B 水 + 1 闪电 -> 1 水晶` 的普通配方：这会让规划器按 N 份线性放大费用，与这里的每单固定成本冲突。

## 吞吐与缓存

用 `R(m)` 表示安装 m 个矩阵时的产量速度。建议按产物数推进进度，理想处理时间为 `ceil(N / R(m))` 个有效游戏刻，再加上资源和输出等待时间。实际曲线、单位和上限尚未确定。

- 矩阵不再使用普通版的八倍产量效果。
- 安装、取出矩阵只能影响后续生产速度，不能改写订单数量、重复交付或重新扣费。
- 采用整批计数与有限次数的存储插入，不按每个产物创建任务、物品实体或回调。
- 订单计数与物品槽位分离。大订单可以分批产出和回流，不能用单个超大 `ItemStack` 表示全部待产数量。
- 普通版的 16,384 与猪咪版的 64 输出槽限制不自动构成过载订单上限。过载版的缓存容量、待接订单上限及持久化计数范围另行确定。
- 网络暂时不能接收时，保留已完成未交付的数量并暂停；恢复后继续精确交付。

## 状态与取消

建议持久化：任务归属、配方及产物快照、催化剂要求、已接收数量、已生产数量、已交付数量、待回流产物、费用快照及是否已支付。

母岩变更、模式变更或数据包重载不能将已接收订单悄悄改成另一种产物。建议暂停不再满足条件的订单，并保留原有归属与进度。

实现前需要明确取消行为：尚未开工的订单是否释放保留资源，已开工订单的固定费用是否退还，已生产产物在 CPU 取消后如何回收。拆除设备也必须有可验证的回收策略，避免丢失或复制待交付产物。

## 候选扩展：合入多方块过载处理工厂

本节将“处理方面二合一”按过载水晶催化与过载材料加工合入同一座工厂讨论。推荐一个控制器、一个对外订单服务、两类可同时工作的生产单元。统一资源接口、订单列表、矩阵管理和产物回流，各自保留配方与费用规则。以下属于建议，尚未确认为实现规格。

### 两类生产能力

| 项目 | 催化单元 | 加工单元 |
| --- | --- | --- |
| 配方来源 | `CrystalCatalyzerRecipe` | `OverloadProcessingRecipe` |
| 能力解锁 | 常驻母岩或其他合法催化剂 | 工厂支持且由玩家启用的加工配方 |
| 原料 | 催化剂常驻、不消耗 | 按配方消耗物品与流体 |
| 订单数量 | 请求 N 个最终产物，交付 N 个 | 接收 K 份配方，按每份产出结算 |
| 流体与闪电 | 沿用前述每单一次的固定费用 | 建议先沿用现有加工配方随份数增长的消耗 |
| FE | 是否需要仍待定 | 建议保留现有加工 FE 规则，另定多方块供能上限 |
| 矩阵 | 提高催化吞吐 | 提高加工吞吐 |

加工配方若每份产出多个物品，规划器可能需要向上取整配方份数。不能把催化订单“精确 N 个”的规则直接套到加工订单，也不能将催化的每单固定成本套到所有加工配方。加工配方现有 FE 计算包含并行倍率公式，并非简单的单份 FE 乘以 K；新工厂若调整公式，需要单独定稿。

推荐两类能力同时暴露订单，不设置整台机器只能二选一的全局模式。玩家可以关闭某类能力，或在控制器中选择启用的加工配方。同一产物存在多个来源时显示来源与消耗，允许选择；不需要物理样板或外部供应器。工厂只提供已支持的两类配方，不自动变成任意机器配方的通用执行器。

### 结构建议

初版建议固定 **5 × 5 × 5**，内部布置中央过载核心、催化仓与加工仓，外壳预留控制器、ME 接口、流体和 FE 接口。结构尺寸仅为候选，具体方块清单、仓位数与成本待确定。

- 催化仓保存多种不退化母岩；分级版本只接受无瑕。不同催化剂解锁不同产物，增加母岩种类扩大配方覆盖，同种母岩堆叠不自动增加速度。
- 加工仓提供同时执行不同加工订单的工作位；增加工作位主要提高任务并发，速度仍受全厂矩阵和供能预算约束。
- 矩阵集中安装与管理，避免玩家逐仓装卡。工作位数量、矩阵吞吐、输入输出缓存分别显示，不能混为同一个“并行数”。
- ME 接口是多方块自身的网络接入部件，直接提供订单能力，不是外部样板供应器。初版建议只有一个有效订单接口，避免重复发布配方和重复接单。
- 催化与加工需要不同流体时，可以同时缓存；不能让全厂唯一流体槽互相卡住。加工配方已有流体输出，回流也必须支持流体。
- 控制器统一显示订单、缺少资源、催化剂、矩阵分配和缓冲区。初版不引入可变长结构、额外散热系统或独立库存补货模式。

### 矩阵与调度

建议采用全厂共享的矩阵吞吐预算，两类单元按需要分配；不能每个仓位都完整享受全厂矩阵倍率。空闲能力可以借给另一类任务，界面可以设置催化/加工权重或保留份额；缺料、缺流体或输出堵塞的任务不占用可运行任务的全部预算。

速度统一按“可完成的工作量”分配，但两类工作使用各自的标尺：催化按产物个数，加工按配方份数及工作量。高耗能配方不能仅因接入相同订单接口就获得与简单配方相同的瞬时速度。

可供第一轮平衡验证的催化数值示例：每枚矩阵提供 64 个水晶/t，候选上限 64 枚；独占预算且资源、回流充足时为 4,096 个/t，即 81,920 个/秒（20 TPS），约为当前普通版满配 16,384 个/秒的五倍。**这是建议起点，不是已确认数值或实测性能**；加工速度不直接照搬这个产物数，混合运行时催化速度随实际分配下降。相比尚未发布的其他模组方案，应优先以现有普通版和工厂的实际吞吐作为平衡基线。

订单只占用有上限的工作状态，按整批数量推进；矩阵多不意味着每 tick 创建更多单件任务。结构检查采用事件触发和合并更新，不为每个外壳方块增加独立生产循环。

### 连续加工与资源归属

目标体验是玩家请求最终加工产物，AE2 规划器根据工厂暴露的配方安排水晶前置订单，再安排材料加工。第一版建议由 AE2 继续负责依赖规划，工厂负责执行，产物先经合成系统确认，再成为后续加工输入。

例如某个已启用加工配方需要水晶时，催化单元先完成相应水晶订单并回流，加工单元随后接受规划器分派的原料。初版不加入绕过 CPU 的厂内截留与私自转料，以免等待清单、计费和取消时的资源归属不一致。

- 加工原料由合成系统按份分派，工厂接收后保存在该任务的输入记录中。避免从 ME 另行抽取同一份原料，造成重复消费或抢走其他任务材料。
- 同一 CPU 任务下的催化与加工子订单各有自己的配方、数量及付费状态。共享一个控制器不等于合并成一次催化开工费。
- 调度跳过暂不可运行的订单，不能让等待水晶的加工订单堵住生产该水晶的催化订单。
- 限制未交付产物缓冲和输入保留量，并为资源充足的前置订单保留可用工作机会；缓存满时停止接收相应工作，而不是无限排队。
- 缺资源时显示具体原因；取消、断网、结构失效和拆除时，未加工原料、已生产产物与已付费用分开处理。失效后暂停执行并保留任务归属，不继续从已移除的仓位生产。

### 代码落点与落地顺序

当前单方块工厂已经有九物品输入、一物品输出、流体输入输出、矩阵并行和 FE 处理逻辑。默认每枚矩阵提供 8 次并行，上限 32 枚，即最多 256 次；加工至少 4 个有效游戏刻，实际时间还受 FE 供给限制。它根据本地原料自动选择一个锁定配方，尚未提供这里需要的原生订单服务。

建议复用两类配方定义、加工匹配与消耗校验、现有多方块的结构扫描和接口分工经验；新增工厂自己的订单执行状态。不要直接把现有单锁定配方的 `OverloadProcessingFactoryBlockEntity` 扩成同时处理多类订单的大型继承层，也不要把物质扭曲矩阵的专用结构和制作规则原样套入工厂。

实施建议按以下顺序验证，每一步通过后再扩展：

1. 先打通单个催化订单与单个加工订单的原生发布、接收、回流；验证催化按单计费以及加工按配方结算。
2. 加入多方块、多个常驻催化剂、加工工作位和共享矩阵调度。
3. 验证同厂“催化 → 加工”的真实递归合成、两类订单混跑、缺料跳过及缓存堵塞恢复。
4. 完成取消、存档重载、结构拆除与费用去重验证，再确定最终吞吐与容量。

## 实现前待定

- AE2CS 分级方案公开后，核对无瑕物品 ID 及生长行为；当前沿用已核对的不退化母岩，不将未来注册名作为本轮阻塞项。
- 是否将过载催化全部并入多方块工厂，以及是否采用上述候选结构；尺寸、材料、仓位数与层级尚未确认。
- 矩阵数量与速度的关系、矩阵槽上限，以及零矩阵时能否工作。
- 常驻催化剂的最低数量、槽位数，以及是否开放粉化模式。
- 每单固定费用的子订单边界；同一订单跨设备分流如何收费。
- 订单上限、并发数量、缓存容量和取消/拆除策略。
- 流体来源、是否额外耗 FE，以及短缺资源的界面提示。
- 机器配方、模型、GUI 和名称。

## 验收要求

- 适配每个母岩版本时核对自然生长不会退化；分级版本逐一验证无瑕母岩可用、会退化的等级在普通版、猪咪版、自动输入和过载订单发布中均被拒绝。不能仅用旧版无分级母岩的测试宣称已支持未来分级版本。
- 真实 AE2 网络中，放入母岩后无需供应器或物理样板即可从终端下单。
- 没有订单时，长时间运行也不产生水晶、不扣流体和闪电。
- 分别请求 1、8、16,384 及超过缓存容量的数量，最终交付严格等于请求数。
- 同一订单跨多次分派和存档重载仍只收费一次；不同订单不能共用一次收费。
- 特殊流体配方扣除正确的流体和闪电阶级；资源不足或输出堵塞时不丢数量、不重复付费。
- 矩阵改变吞吐，产量和总费用保持不变；催化剂与矩阵全程不消耗。
- 覆盖订单取消、CPU 移除、断网、换母岩、数据包重载、区块卸载和拆机。
- 普通版与猪咪版继续满足本次确认的母岩 1 出 8 和各自矩阵规则；输出容量分别为 16,384 和 64。
