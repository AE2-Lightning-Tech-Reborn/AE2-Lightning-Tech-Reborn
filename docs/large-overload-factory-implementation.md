# 大型过载处理工厂：本代独立实现进度

本代先在 LT Reborn 内实现专用工厂，通用多方块框架留到下一代。不新增 TB 框架或仓室 API；后续 ME 批量交互继续使用既有依赖。普通核心的吞吐、FE 数值与制造配方尚待平衡，不把旧稿数值当成已确认配置。

## 已落地的首批内部逻辑

- `machine.largeoverload.LargeFactoryStructure`：固定 9×7×9 格子表、四个水平朝向、背面九仓位、逐区块可用性检查及有界诊断。普通工厂需要样板仓或水晶仓，苍穹工厂必须有样板仓；苍穹位置与库存／任务状态由实际核心接入层提供。
- `LargeFactoryStructureOwnership`：每个世界的成员独占；先检查全部成员再绑定，旧令牌无法取得重建后的权限；内部空气变化和覆盖区块卸载可使绑定立即失效。世界事件接线尚未实现。
- `LargeFactoryRecipeAccess`：按源配方类型判断基础目录和工艺核心权限，苍穹模式只开放苍穹转换。权限通过不代表第三方适配器已经实现，也不绕过 RecipeManager 中的存在性检查。
- `LargeFactoryLightningCost`：普通配方至少 1 高压、保留较高源成本；苍穹每次 1 极高压；仅允许 4 高压补足 1 极高压。按源操作计费，支持部分数量报价与精确溢出拒绝，尚不执行网络扣除。
- `LargeFactoryOperationBudget`：所有仓室将共用的每 tick 累计额度；预留防止回调重入超发，完成不返还当 tick 额度，四倍样板按四次源操作结算。苍穹上限固定 1,024，普通核心由后续配置提供容量。

## 当前验证

Java 21 编译及 `com.moakiee.ae2lt.machine.largeoverload.*` 的 32 项 JUnit 测试通过。包括各朝向结构、非法仓位、缺失区块不读世界、扫描途中卸载、核心接管条件、相交所有权、失效令牌、费用上下限、4:1 单向代偿、批次拆分、BigInteger 费用对照以及预留／提交／取消的额度守恒。

验证依赖由未修改的 TB alpha `ac04c10f1a09cd5c2cef3655dd623ca681a2d54f` 使用 Java 21 隔离构建，确认 class major 为 65；没有使用本机被 Java 25 产物覆盖的同版本 Maven 缓存。LT 基线为 alpha `4b5e9edc655a8b7104358679deaf7a566e307b1b`。

## 尚未完成

本提交是内部逻辑的第一阶段，不是游戏中可使用的完整机器。方块／物品注册、控制器和仓室 BlockEntity、网络节点、GUI、样板存储与发布、实际配方绑定、真实支付与资源恢复、0t 产出回传、被动调度、第三方配方适配及模型材质均尚未接入；未运行整机 GameTest 或客户端实测。

下一步接入本机方块和控制器生命周期，完成结构事件与独占绑定，再实现 36／144 槽样板仓、基础两类配方和费用／产物账本的可执行闭环。苍穹接管必须同时处理原单机入口互斥、星舰归属和已有库存，不得只依据扫描成功就停用旧核心。
