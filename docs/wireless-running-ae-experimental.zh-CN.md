## 已核实的依赖事实

检查的是构建实际声明的 AE2 19.2.17 与 Applied Flux Curse 文件 7429565，不采用缓存中其他版本推断。

- AE2 `EnergyService.extractAEPower` 先应用 `PowerMultiplier.multiply`，遍历普通供能服务，然后 `divide` 并返回。`onServerEndTick` 的闲置扣电经过同一函数，随后才更新 `hasPower`，因此返回处是候选的“当次缺额补足”位置。
- `isNetworkPowered()` 只返回 `publicHasPower`。实验钩子另外检查 `hasPower`，要求二者已为真，避免利用首次启动的状态滞后来启动断电网。此判定仍须真实 GameTest 验证。
- 本版本换算类型是 `appeng.api.config.PowerUnit`（单数），FE 转 AE 使用 `PowerUnit.FE.convertTo(PowerUnit.AE, amount)`。不能照其他版本的 `PowerUnits` 名称实现。
- `StorageService.getInventory()` 返回 `NetworkStorage`；直接 FE 提取没有自身的 AE 收费调用。`NetworkStorage` 的嵌套提取受 `mountsInUse` 保护，但外部挂载仍可回调，因此实验路径另有按网格重入闸门与来源有效性校验。
- 高级控制器原本每 tick 被动产生 AE，不能把这部分当成 FE 兑换结果。后续测试必须显式区分正常供能与 FE 补缺额，尤其是断电/冷启动测试。

本机反汇编证据位于未提交的 `build/verification/fe-to-ae-analysis/`；没有将原始开发日志或依赖反编译内容提交。

## 已准备但未验证的实现

1. 默认关闭的服务端实验配置 `wirelessControllerEnergy.runningNetworkFeFallback`。这不决定未来控制器 UI 或正式默认开关值。
2. `RunningNetworkFeFallbackMixin` 在原 AE 提取返回后补缺额，仅选本 `IGrid` 中活跃的高级控制器，不沿能源覆盖网络借用其他网格 FE；普通 AE 足够时不提取 FE。
3. 使用现有网格共享 FE/访问预算，拓扑变化当 tick 暂停。模拟读取预算、FE 和 AE 余量，不扣款或创建节点账户。真实请求按实际 FE 回执结算。
4. `AeEnergyBalance` 保存已转换的原始 AE，小数以十进制字符串持久化；使用原节点 UUID 账户随节点迁移，不合并/复制网格余额。已转换余量不因后续兑换率变化被重新定价，也不能反向发作 FE。
5. 外部提取前保存尚未确认的 FE 提取上界。异常或重启留下该记录时停止自动补能；它不是已拥有、可花费或可退款的 FE。正式回执先进入原 FE 托管账户，再转换；退款/拓扑回调完成之后才提交本次 AE 支付。
6. 已写 8 项针对小数精度、模拟不变、兑换率变化、未确认提取、存档恢复、非法值、随机守恒和预算预览的 JUnit；全部未运行。已有 6 项整数账本测试亦未在此实验补丁上重跑。
