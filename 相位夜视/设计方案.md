# 相位夜视与 X-ray 设计

状态：设计阶段，尚未实现。更新日期：2026-10-27。目标仓库为 AE2-Lightning-Tech-Reborn，现有实现参考 Minecraft 1.21.1、NeoForge；功能开发分支与移植版本在实施时确定。

相位夜视模块作为普通夜视模块的上位版本，保留持续夜视，并解锁穿透遮挡观察目标方块的 X-ray 能力。目标筛选、显示方式与数据来源按下述方案设计；具体范围、配方和能耗尚未确定。

## 功能分级

| 功能 | 普通夜视模块 | 相位夜视模块 |
| --- | --- | --- |
| 持续夜视 | 保留 | 保留 |
| 穿透遮挡观察目标方块 | 不提供 | 解锁 |
| 按方块 ID 或标签筛选目标 | 不提供 | 作为透视配置提供 |
| 目标轮廓高亮与遮挡方块淡化 | 不提供 | 候选显示方式 |

普通夜视维持现有定位，不因新增上位模块而获得透视。相位夜视只改变视觉，方块碰撞、挖掘距离、射线交互和服务器权限仍遵守原有规则。能看见隔墙方块不代表可以隔墙挖掘或打开容器。

## 开关与目标筛选

建议夜视与 X-ray 分别提供开关，允许保持夜视并按需开启透视，也允许独立关闭夜视增亮。建议相位夜视与普通夜视作为同类头盔模块互斥安装，由上位模块承担完整功能，避免重复施加或移除同一种夜视效果。互斥安装、默认开关状态与快捷键方案仍属于候选配置。

目标筛选采用方块注册 ID 或方块标签，矿物可作为首批预设，指定方块和容器方块可作为其他预设。容器识别仅表示其方块位置，不读取容器内物品。不同矿物、模组方块与预设的具体覆盖范围需要按实际注册项和标签验证。

空白筛选建议表示不显示目标，不自动扩展为透视全部方块。无效 ID、缺失模组或不存在的标签应给出可理解的提示；修改筛选或重载标签后，旧目标缓存必须失效。范围、颜色与透明度可配置，但上限和默认值在实现时确定。

## 候选显示方式

| 模式 | 显示目标 | 实现约束 |
| --- | --- | --- |
| 轮廓高亮 | 透过遮挡显示所选方块的边框或轮廓，保留正常场景以帮助定位 | 在独立渲染步骤中处理遮挡，不将全场景深度测试永久关闭 |
| 遮挡方块淡化 | 降低范围内非目标遮挡方块的不透明度，突出目标方块 | 需要处理目标面的绘制、遮挡剔除、透明排序和模式切换后的场景重建 |

两种模式都需要保证完全被不透明方块包围的目标仍能显示。仅修改光照或降低已有网格透明度，不能保证原本被剔除的目标面出现。若采用方块边框表达目标，应与实际方块模型区分，不能把轮廓实现描述成完整模型透视。

显示效果只作用于使用者当前视图，不改变其他玩家看到的世界。关闭 X-ray 后恢复正常遮挡和透明状态；卸下模块、失效、死亡、重连或切换维度时清理对应显示与缓存。夜视开关保持独立，不因关闭透视而额外熄灭仍启用的夜视。

## 客户端数据与服务端职责

建议首版基于客户端已经收到且仍加载的区块数据构建目标列表，由服务端判断相位夜视模块是否有效、同步功能状态，客户端负责筛选缓存与绘制。扫描不主动请求或强制加载远处区块。

纯客户端渲染只能展示已有数据，不能还原服务器尚未发送或已经替换隐藏的真实方块。客户端数据不足时，应按可用数据展示，不能将未知区域当作已经确认没有目标。

如果后续要求显示客户端没有收到的真实方块，需要另行设计服务端扫描与目标同步，明确扫描范围、模块有效性、数据更新频率及网络开销。这项扩展不作为首版纯客户端 X-ray 的默认能力，也不通过更改世界或强制生成区块补齐信息。

实际头盔与模块状态应通过统一装备解析获取，兼容护甲已进入私有相位槽、普通装备槽只保留投影的情况，参见[过载相位锁定设计](../过载相位锁定/设计方案.md)。相位夜视不要求同时开启相位飞行，已有相位飞行的可见性处理也不能作为模块已解锁 X-ray 的判断条件。

## 缓存与渲染兼容

目标索引建议按区块或区段缓存，首次扫描分批执行，方块更新后增量刷新。玩家移动、调整范围或筛选、区块加载与卸载时只更新受影响部分；不在每个渲染帧扫描全部方块。

绘制时限制可见范围与工作预算，缓存键包含维度和位置，避免切换维度后残留旧目标。关闭功能后停止相关扫描并释放不再使用的缓存。具体预算、缓存容量与帧时间目标待测量后确定。

原版渲染、替代区块渲染器与光影需要分别验证。轮廓高亮与遮挡淡化的兼容程度可能不同；某组合只支持其中一种模式时，应明确显示可用模式，不能用部分可见目标替代完整遮挡测试。已有相位飞行的区段可见性修改仅是相关接入参考，不等于完成目标筛选、透视绘制或渲染模组兼容。

## 验收目标

- 普通夜视没有新增透视能力，相位夜视的夜视与 X-ray 开关分别生效。
- 所选矿物或指定方块在完全被遮挡时仍能按所选模式显示；未选中的方块不会误作目标。
- ID、标签、空白筛选、无效目标及数据包重载后的行为符合确定的配置规则。
- 开关、卸装、模块失效、死亡重生、重连和切换维度后没有残留目标、透明状态或异常深度状态。
- 相位槽中保存的实际头盔可正确识别；仅开启相位飞行不会误启用 X-ray。
- 未收到或已卸载的区块不会显示为已扫描完成，不因透视触发强制加载或改变世界状态。
- 挖掘、碰撞、容器交互、服务器权限和其他玩家视图保持原有行为。
- 在大量目标、快速移动和区块更新下验证扫描与渲染预算；分别记录原版、替代渲染器及光影的兼容结果。

实施前还需确定显示模式的交付顺序、初始目标预设、范围与颜色默认值、能耗、升级配方、配置保存位置及是否加入服务端扫描扩展。
