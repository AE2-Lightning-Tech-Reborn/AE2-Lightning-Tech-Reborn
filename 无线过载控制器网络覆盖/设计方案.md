# 无线过载控制器的网络无线覆盖设计

状态：设计阶段，尚未实现。更新日期：2026-10-28。目标仓库为 AE2-Lightning-Tech-Reborn；实现参考 Minecraft 1.21.1、NeoForge 与 AE2 19.2.17，具体开发分支和其他版本适配另行确定。

无线过载控制器为所在 ME 网络增加同维度无限距离无线覆盖，高级无线过载控制器增加所有维度无线覆盖。只要网络中存在有效的对应控制器，已绑定该网络的无线设备就能在覆盖范围内连接，无线终端是首要接入对象。能力属于整个网络，不限定设备必须绑定提供覆盖的那一台控制器。

## 功能分级

| 所在网络的有效控制器 | 新增覆盖能力 |
| --- | --- |
| 无无线过载控制器 | 保留设备和原有无线访问点的接入规则 |
| 无线过载控制器 | 覆盖该控制器所在维度，忽略坐标距离限制 |
| 多台普通无线过载控制器 | 覆盖这些控制器所在维度的并集 |
| 至少一台高级无线过载控制器 | 覆盖所有可用维度，忽略跨维度与坐标距离限制 |

这里的“网络中有”指控制器当前实际接入该 ME 网络且能够提供服务，不是物品放在存储里、方块在附近或曾经登记过。网络仍需处于可用状态；失效、冲突或卸载的控制器不提供覆盖。

此能力不要求控制器先配置无线发射频率，也不要求额外摆放原版无线访问点或安装范围升级卡。频率式方块联网继续使用原有频率、绑定和频道规则，不因终端覆盖而自动连接世界中所有未绑定设备。

## 绑定与使用流程

1. 将普通或高级无线过载控制器接入目标 ME 网络，网络可用时自动具备相应覆盖能力。
2. 无线设备通过其正常绑定流程选择目标网络。控制器需要提供受支持设备可用的绑定入口，具体交互形式在实现时确定。
3. 已绑定该网络其他有效访问点的设备，也能获得网络级覆盖，不要求重新绑定到提供覆盖的控制器。
4. 普通版允许设备在对应维度任意距离使用；高级版允许设备跨维度使用。设备操作仍经服务端解析绑定和校验。

已有绑定必须能够可靠解析到当前网络。原绑定节点被拆除、替换或未加载，导致网络无法解析时，不凭历史缓存认定它仍指向原网络，也不自动改连附近其他网络。若需要在原绑定锚点失效后继续寻址，应另行设计稳定网络身份与迁移规则。

覆盖只放宽无线距离和维度条件。终端电量、网络运行状态、设备原有权限及存取检查继续生效；未绑定、绑定错误或无权访问时不能连接。网络覆盖本身不赋予额外存取权限。

## 无线设备范围

目标是覆盖接入该 ME 网络的受支持无线设备，而不是只为某一种终端增加特例。首批接入与验收应包含以下路径：

| 设备路径 | 接入要求 |
| --- | --- |
| 原版 AE2 无线终端 | 网络级覆盖参与打开界面后的持续连接检查与存取操作 |
| LT 天枢无线合成终端、无线样板编码终端 | 沿用各自功能，同时接入统一覆盖判定 |
| AE2WTLib 支持的无线终端及通用终端组件 | 核对公共宿主和组件切换路径，不因切换页面丢失覆盖 |
| 其他 AE2 附属无线设备 | 复用共同接入逻辑，或针对独立的寻网、距离与维度检查逐项适配 |

第三方模组自行实现的无线协议不会因控制器存在就自动兼容。最终文案与兼容列表必须区分已验证设备、需要适配的独立实现，以及并不访问 ME 网络的其他无线设备。已经具有更强接入能力的设备保留其原有行为，不因本功能将其降级。

终端覆盖与无线 FE 供电是独立能力。此处普通版同维度、高级版跨维度的分级，不代表能源功能也下放到普通版，参见[无线过载控制器能源与频率卡供电设计](../无线过载控制器能源/设计方案.md)。

## 网络级判定与生命周期

建议由网络级服务维护有效普通控制器的维度集合，以及有效高级控制器是否存在。设备先解析自己的目标网络，再查询该网络对设备当前维度的覆盖；不能先全服寻找一台控制器，再把覆盖授予无关网络。

控制器加入、移除、节点失效、维度卸载及网络拆分合并时，更新覆盖状态。网络拆分后，每个子网只保留自身控制器提供的覆盖；合并后按新网络聚合。高级控制器移除后，如果还有普通控制器，降级为其维度集合；新增覆盖不成立时仍可尝试原有访问点和设备自身的接入路径。

服务端持续检查正在使用的设备，不能只在打开终端时检查一次。跨维度移动、网络掉电、控制器失效或绑定变更后，界面连接状态和实际存取结果必须一致。能力恢复时允许按设备原流程重新连接。

覆盖不等于区块加载。控制器和用于解析网络的绑定节点必须处于相应接口要求的有效加载状态；本功能不主动生成维度或强制加载远处区块。需要常驻网络时仍由原有区块加载方案负责。

覆盖统计应在拓扑或节点状态变化时维护，设备查询复用当前网络结果，不按每个终端、每个 tick 扫描全世界。缓存必须校验当前网络归属并随网络生命周期失效，避免拆网后沿用旧覆盖。

## 接入点与耗电处理

AE2 19.2.17 的 `WirelessTerminalMenuHost.updateConnectedAccessPoint()` 按 `WirelessAccessPointBlockEntity` 枚举原版访问点，并通过 `getAccessPointSignal()` 检查维度和距离。因此，仅让控制器实现 `IWirelessAccessPoint` 或返回极大范围，不足以让原版终端自动采用它。

实现需要打通两层：控制器可作为合法绑定锚点，使无线设备能够解析目标网络；网络覆盖服务参与终端的信号与持续连接判定，使绑定同网其他节点的设备也受益。实际接入位置应尽量复用公共宿主，独立覆盖逻辑则单独适配。

LT 天枢无线终端当前基于 AE2WTLib 的 `WTMenuHost`。该宿主及第三方组件的覆写行为需要单独核对，不能把原版 AE2 终端接通作为全部终端已经兼容的证明。

无限范围不表示免费使用。终端自身耗电与网络能源规则保留，但不能把 `Double.MAX_VALUE`、无穷值或跨维度坐标差传给按距离计费的公式。新增覆盖路径需要定义有限、可解释的耗电规则；固定接入成本或有限等效距离可作为候选，具体数值待定，多个控制器不重复计费。原有访问点路径继续使用其原规则。

用户界面建议区分“同维度网络覆盖”“跨维度网络覆盖”和原有有限距离访问点，不用虚构的超大距离表示覆盖状态。未绑定、绑定节点不可用、网络不可用、无相应覆盖与终端电量不足应沿用或补充准确提示。

## 验收目标

- 普通无线过载控制器支持同维度远距离接入，跨维度不会错误获得新增覆盖；高级版支持跨维度接入。
- 网络中无原版无线访问点、控制器未设发射频率时，设备仍可通过控制器绑定并使用新增覆盖。
- 已绑定同网其他有效访问点的设备无需重绑，仍获得网络级覆盖；绑定另一网络的设备不能借用覆盖。
- 多个普通控制器按所在维度合并覆盖；高级控制器移除后正确降级，最后一个有效控制器移除后撤销新增覆盖。
- 网络拆分、合并、卸载、重载、冲突、掉电与跨维度移动后，无旧网络覆盖残留，正在打开的终端状态与实际操作一致。
- 无绑定、权限不足、电量不足或绑定锚点失效时，不能因覆盖跳过原有检查。
- 原版 AE2、两种天枢终端、AE2WTLib 通用终端组件和其他适配设备分别验证打开、存取、切换页面与持续连接。
- 多人同时使用时覆盖归属正确，耗电有限且不重复；大量设备查询不退化为逐设备全网或全世界扫描。
- 不改变频率式方块联网的频道限制、绑定规则或无线 FE 供电准入，也不削弱设备原有的独立远程接入能力。

实施前待定：控制器的终端绑定交互、公共覆盖服务与兼容注入位置、新增覆盖路径的计费规则，以及首批第三方设备兼容清单。
