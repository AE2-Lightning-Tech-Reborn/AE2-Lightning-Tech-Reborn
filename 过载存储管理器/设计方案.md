# 过载存储管理器设计方案

状态：设计草案，尚未实现。更新日期：2026-10-27。目标仓库：AE2-Lightning-Tech-Reborn。当前接口核对基于 Minecraft 1.21.1、NeoForge、AE2 19.2.17 和 LT Reborn `alpha`；其他版本需要分别验证。

过载存储管理器用于查看 ME 网络内各个存储来源，展开驱动器中的具体磁盘，并通过任务将选定资源搬到指定目标。玩家可以保留磁盘在驱动器内，完成单盘检查、分类整理和旧盘迁移。候选名称曾为“过载磁盘管理器”；由于规划同时覆盖存储总线及其他存储来源，本文采用“过载存储管理器”，最终物品名称和注册 ID 待实现时确定。

## 定位与范围

网络终端继续提供整个网络的汇总库存。管理器补充“资源在哪个来源、哪张盘，以及搬到哪里”的管理视图，不要求玩家重新按盘组织日常存取，也不引入文件夹、文件复制和盘符等完整文件系统概念。

| 设备 | 职责 |
| --- | --- |
| 过载 IO 端口 | 磁盘与 ME 网络之间的批量填充、清空、过滤和自动化输入输出 |
| 过载存储管理器 | 按来源查看库存、逐盘查看、选择源与目标、创建和执行定向搬运任务 |

建议以独立设备承载管理器，复用已有原生资源搬运逻辑，不把过载 IO 端口的完成盘输出槽改成目标盘槽。当前 IO 端口有六个输入槽和六个完成盘输出槽；后者接收处理结束的磁盘，并不表示盘对盘搬运的目标。

首批使用场景：

- 拆走旧盘前，检查它装了什么，并将内容迁往指定新盘。
- 将散落在不同磁盘的指定材料集中到一张盘，或从混合盘中只取出选中的材料。
- 查看容量或类型占用异常的盘，定位具体资源。
- 后续扩展到存储总线及受支持第三方设备，在统一界面内辨认不同存储来源。

## 网络、来源与磁盘层级

AE2 的网络存储服务提供汇总库存，存储提供器向服务挂载具体库存。管理器中的“分开”是按来源显示和操作，不是拆分 ME 网络；正常终端仍按原规则使用整个网络。

建议界面按以下层级组织，树中的名称仅为示例：

```text
当前 ME 网络
├─ ME 驱动器 A
│  ├─ 槽位 1：物品存储元件
│  ├─ 槽位 2：流体存储元件
│  └─ 槽位 3：第三方存储元件
├─ ME 驱动器 B
│  └─ 各槽位的磁盘
├─ 存储总线 A → 抽屉
└─ 存储总线 B → 箱子
```

点击来源显示其可见内容，展开驱动器后可切换到单个槽位的磁盘。列表显示设备名称、可定位的位置、在线状态及可用的读写能力；同名设备、同类型磁盘必须能通过位置和槽位区分。不能定位到物理方块的提供器使用独立来源标识，不伪造坐标。

驱动器级视图汇总已识别子盘，标明数据覆盖范围；容量、类型和资源单位不能简单跨类型相加。网络总览沿用网络汇总语义，不将父来源与子盘的显示数量重复累加。多个存储总线可能暴露同一外部库存，来源列表不天然等于一组互不重叠的物理仓库。

设备离线、区块卸载或磁盘被替换时，来源显示失效状态，不能继续把旧快照当成可操作的实时库存。第一版只管理当前网络可访问的在线来源，不主动加载远程区块，也不跨越子网自动展开另一网络的全部设备。

## 驱动器与磁盘分别适配

| 层次 | 负责内容 | 兼容边界 |
| --- | --- | --- |
| 来源识别 | 找到网络实际使用的存储来源，提供名称、位置、可用状态及库存入口 | 通用接口不保证完整枚举所有全局提供器，也不保证所有提供器都是物理仓库 |
| 驱动器适配 | 枚举槽位、识别磁盘、关联槽位与正在使用的库存实例 | 原版驱动器优先；第三方驱动器按自身槽位和挂载方式单独适配 |
| 磁盘适配 | 读取内容、按原生资源键存取、读取容量及类型等元数据 | 标准存取优先使用通用接口；特殊显示字段按需补充 |

这两类适配组合使用，不为每种“驱动器 × 磁盘”重复实现搬运。遵循标准存储接口的第三方盘可以尝试通用路径，但不能在未验证前宣称全部兼容。

物品、流体、LT 闪电等保留各自原生资源键和单位。无限盘、超大数盘、分区盘和只读盘按实际能力显示；读取不到的容量显示“未知”，不显示为零或自行推断无限。超过单次接口数值范围的数量需要拆分并保留精度，不能截断、溢出或通过浮点数保存任务进度。未支持的能力明确标识，不强制开放搬运。

存储总线应通过网络实际使用、带有过滤与访问限制的库存入口操作。不能直接读取背后的箱子或抽屉来绕过总线规则。合成服务的截流入口、虚拟库存等也不能仅因实现了存储接口，就自动列为可任意清空的磁盘。

## 浏览与创建任务

界面建议分为来源树、当前来源内容区和任务区。内容区沿用终端式资源展示，提供搜索、排序和多选；容量、类型占用、分区和读写状态在能力可用时显示。

玩家操作流程：

1. 在来源树中选定源盘，查看内容。
2. 选择资源并填写数量，或选择整盘搬迁。
3. 选择目标盘，查看目标状态和预检结果。
4. 添加任务，进入等待条件、蓄能、执行和完成等状态。
5. 在任务区查看已搬数量、待搬数量、能量进度及阻塞原因，按需暂停或取消。

第一版的可执行目标限定为已适配的具体磁盘。驱动器汇总视图用于浏览；若后续支持“一整台驱动器 → 另一台驱动器”，需先定义子盘选择和分配规则，不能静默交给网络优先级决定。盘与整个 ME 网络之间的普通填充、清空已有 IO 端口承担，管理器是否另外提供这一入口待定。

搜索仅改变视图，不自动改变任务范围。多选、全选当前结果和整盘搬迁需要明确区分。“整盘搬迁”默认以提交时服务端确认的资源种类和数量为有限清单，不持续追赶随后进入源盘的新资源。它不等同于保证源盘最终为空；界面应显示任务清单之外的新入库资源。

任务提交时保存源、目标和数量清单；执行前重新验证，不提前抽空源盘作为资源预留。源库存可能被正常网络使用，预检成功不等于资源或目标容量已被独占锁定。数量不足时显示等待或部分完成原因，不擅自从其他来源补齐。

## 任务队列与蓄能后执行

新增设计方向：允许玩家添加搬运任务，先收集足够能量，再启动执行。任务式操作将选择、预检、蓄能和执行串成一次完整流程，避免玩家反复手动点击转移。

“一次性执行”需要区分两个含义：

| 含义 | 建议处理 |
| --- | --- |
| 一次提交，充能就绪后完成一项搬迁 | 作为主要交互方向，允许任务跨多个 tick 执行并显示进度 |
| 无论多少资源种类，都在一个 tick 搬完 | 不作为无条件承诺；只有完整工作量落在单 tick 预算内的任务才可当 tick 完成 |

大量同种资源可以通过一次或少量原生存取调用搬运；大量不同种类则需要分别处理。已经收集了足够能量，也不能因此取消每 tick 的资源种类、接口调用和数据同步预算。蓄能就绪代表任务获得执行条件，不代表第三方库存提供了跨盘原子事务。

### 建议调度与状态

首版建议每台管理器一个持久化队列、一个活动任务；其余任务等待调度，支持暂停、取消和调整未开始任务的顺序。队列长度、资源条目数和任务大小需设上限，具体数值待性能验证。

```text
排队 → 预检 → 蓄能 → 再次校验 → 执行 → 完成
         ↘ 等待来源 / 等待空间 / 来源失效
执行 → 等待能量 / 等待空间 / 暂停 / 待处理余量 → 恢复执行
```

排在前面的任务等待条件时，后续任务是否允许显式跳过调度属于界面与调度待定项；不能隐式并行耗能、提取同一份资源。关闭界面不删除任务；机器可运行时由服务端继续执行，区块卸载暂停，不为任务额外强加载。多个管理器和其他网络消费者同时操作时，每批按真实提取、接收结果更新进度，不能将预检结果当作全网库存锁。

每项任务至少保存任务标识、来源与目标身份、资源键及请求数量、已完成数量、状态和阻塞原因。资源不会因为“添加任务”而复制，所有移动都扣除实际源库存。

### 能量模型与大任务

建议沿用 ME 供电体系，以 AE 为第一候选计量；最终成本公式、内部缓冲容量、充能速率和升级方式尚未确定。本草案不直接继承 IO 端口的具体能耗数值，也不默认要求额外的闪电或 FE。

“蓄能”应是实际从网络取得并保存在机器内部的能量，不能只是界面上增加一个数字，也不能把网络现有能量标成每台管理器各自的独占储备。充能受速率限制并遵守网络供电规则，避免瞬间耗尽维持网络运行所需的供电；具体限流和运行余量策略需要验证。

建议先按冻结的任务清单和已知单批限制估算能耗，界面明确标注估算值。目标容量、过滤和在线状态会变化，预检与充能完成后必须再次校验，不能因已充满能量就强行提取资源。

- 小任务：预计完整执行能量不超过缓冲上限时，可先充足整项任务的预计能量，再开始搬运；工作量符合单 tick 预算时可当 tick 完成。
- 大任务：预计能量超过缓冲容量时，提供明确的分批持续执行方式，按有界工作窗口蓄能和搬运；不能永久等待一个机器永远装不下的能量值。
- 能耗估算变化：若实际执行需要更多能量，转入等待能量状态，继续完成原任务剩余清单，不重新搬已经完成的部分。

这是一套建议默认行为；是否允许玩家在“整项蓄能后启动”和“分批持续执行”之间手动选择、整项模式不足以容纳时如何提示，仍待定。两种方式均不能绕过工作预算和源目标校验。

充入缓冲、执行时扣除、未使用余额应分别记账，不能在充能和搬运时重复扣费。暂停或取消任务后，已消耗能量不凭空退回，未消耗余额保留在管理器。拆机和重载必须按确定的持久化规则处理余额，不复制或无故删除；具体回收载体待实现确认。目标模拟接受但实际拒收时如何计费，需要明确并纳入验收。

## 定向搬运与一致性

选择 A 盘到 B 盘时，必须使用两者对应的实际库存入口。不能从网络总库存提取再插回总库存，否则不能保证资源来自 A 或最终进入 B，甚至可能回到原来源。

每批执行前验证当前网络归属、来源在线状态、玩家操作权限、磁盘身份以及读写限制。不能把相同坐标或相同槽位中的替换磁盘视为旧盘继续任务；适配层需提供可验证的身份和变更代次，身份无法可靠恢复时要求重新选择，不能仅凭物品 ID 猜测。

操作需要经过正确的挂载包装及更新通知路径，保留原有过滤、权限、脏标记和库存缓存更新。直接访问原始盘数据的快捷方式不能替代正常存储操作。管理器自身也要校验网络访问权限，不能假定底层存储接口替它完成所有授权。

一批搬运按模拟可提取量、模拟可接收量、本批数量上限和可用能量确定范围，再以真实提取及接收量结算。目标实际接收量减少时，未接收部分优先退回原来源；退回失败则保留为可持久化余量并暂停新的提取，界面提供明确恢复状态。不能静默丢弃，也不能未经选择把它写到其他盘或回到网络总库存。来源已不可恢复时，需提供保留资源的回收或重新指定归还目标路径。

取消只停止尚未执行的部分，已经搬到目标盘的资源保留；待处理余量仍须归还或安全回收。整项任务不承诺跨第三方库存的“全部成功或全部回滚”，不能通过取消把源库存按原始任务数量恢复一遍。

存档保存任务进度、实际持有的余量和内部能量。重载先核对身份与已保存进度，再处理余量，避免重复执行已经完成的数量。拆机不能把非空余量当普通空方块丢弃；回收载体、重放防护及崩溃保存边界需要实现验证，不能仅凭设计声称任意崩溃时序均已保证原子性。

相同端点禁止自搬运。不同来源若确定指向同一物理库存，应合并标识或拒绝互搬；无法排除别名重叠的第三方来源，先限制为只读或未验证状态，不开放无界“搬到清空”为止的循环任务。

## 接口核对与实现边界

以下是代码和接口检查结论，不是游戏内验证结果：

| 核对对象 | 已观察到的能力 | 对设计的影响 |
| --- | --- | --- |
| AE2 19.2.17 `IStorageService` | 提供网络总库存、缓存库存以及提供器增删与刷新入口 | 公共接口未直接提供完整的已挂载提供器列表，不能宣称现成支持任意来源完整枚举 |
| AE2 19.2.17 `IStorageProvider` / `IStorageMounts` | 提供器通过挂载操作提交库存和优先级 | 需要保留来源与挂载库存的关联；不能为了刷新界面反复调用挂载流程并假定没有副作用 |
| AE2 19.2.17 `DriveBlockEntity` | 提供 `getCellCount()`、`getCellInventory(int)` 与 `getOriginalCellInventory(int)` 等逐槽接口 | 原版驱动器单盘管理有明确入口；正常存取仍需核对包装器、权限及通知路径 |
| AE2 19.2.17 `MEStorage` | 可按原生资源键列举、模拟和执行存取 | 可作为通用数据访问基础，但不保证统一容量字段或跨库存事务 |
| LT Reborn `alpha` 过载 IO 端口 | 已有有界搬运、过滤、失败退回和余量暂存逻辑 | 可评估抽取或复用，管理器的指定目标、任务、身份和恢复语义仍需新增 |

LT 代码参考固定在核对时的提交 [`33fa7d72`](https://github.com/AE2-Lightning-Tech-Reborn/AE2-Lightning-Tech-Reborn/tree/33fa7d72d997414204cea466cbc7b49eca19f14c)：`OverloadedIOPortBlockEntity`、`OverloadedIOPortMenu`、`OverloadedIOPortScreen` 和 `OverloadedIOTransfer`。AE2 版本以本地核对的 19.2.17 为准；在线 [IStorageProvider](https://appliedenergistics.org/javadoc/appeng/api/storage/IStorageProvider.html) 与 [IStorageService](https://appliedenergistics.org/javadoc/appeng/api/networking/storage/IStorageService.html) 文档用于解释接口职责，可能跟随上游版本更新。

完整来源目录的实现可以评估监听实际挂载生命周期并维护来源索引；具体接入点尚未选定。第一版优先使用原版驱动器适配，不把“遍历网络节点”当作能覆盖全部全局提供器的保证。索引和缓存必须响应来源卸载、网格拆分合并、槽位变化及能力失效。

浏览只读快照，服务端校验所有修改。只订阅当前展开来源、当前页及相关活动任务的变化；限制枚举、分页、同步和任务工作量，避免每个玩家打开界面就每 tick 扫描全网所有磁盘。第三方一次接口调用本身可能昂贵，需要实际测量，调用次数预算不能被表述为已经证明的耗时上限。

## 分阶段实施建议

| 阶段 | 内容 | 交付边界 |
| --- | --- | --- |
| 第一阶段：浏览 | 当前网络原版 ME 驱动器、逐槽磁盘内容、搜索及状态 | 明确元数据缺失和未支持磁盘，不承诺任意来源全覆盖 |
| 第二阶段：任务搬运 | 明确源盘与目标盘，有限数量清单，队列、预检、蓄能、暂停取消、持久化和余量恢复 | 原版驱动器内的受支持磁盘先完成端到端验证 |
| 第三阶段：来源扩展 | 存储总线、第三方驱动器、特殊磁盘元数据与其他受支持来源 | 每类单独验证读写限制、重复映射和恢复，不按模组名称泛称全部兼容 |

上述是设计拆分，不表示已经开始实现。管理器自身是否提供本地插盘槽、槽位数量、外观、配方、频道要求、能耗公式、蓄能容量与速率、升级物品及全网来源索引接入方式均待确定。

## 验收要求

- 原版驱动器内不同盘的内容分别准确，切换槽位不混盘；父子视图不重复统计。
- A 盘到 B 盘的任务只改变选定端点；网络其他盘保持正常使用，任务不经网络优先级重新分配目标。
- 过滤、只读、类型不兼容、目标容量不足和来源数量变化有正确反馈；不使用未授权来源补量。
- 大量同种资源与大量不同种类分别验证，保留数量精度，浏览、同步和执行均满足有界工作要求。
- 任务达到所需能量前不提取资源；充能与执行不会重复扣费；超过缓冲容量的大任务不会永久等待不可达到的条件。
- 小任务在预算允许时可当 tick 完成，大任务分批执行；充能完成不绕过预算、容量和权限校验。
- 玩家关闭界面、暂停、取消、区块卸载、网络重连、正常保存重载和拆机时，已完成数量、余量和能量均按规定保存与恢复。
- 模拟后拒收、源也拒收、源盘被替换、目标被移除时不丢失或复制资源；替换盘不会继承旧盘任务身份。
- 多任务、多玩家、多个管理器及正常网络消费者竞争同一库存时，按实际接收量计入进度，不超额提取或重复交付。
- 存储总线重复映射、子网代理、虚拟来源和第三方盘异常能力有明确支持边界，不误导为全部可安全迁移。
